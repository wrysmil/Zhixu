# 记忆评测前端设计草案

这是已有记忆评测方案的界面细化，不代表页面已实现，也不改变原计划的审批状态。下文数值均为界面示例。

## 1. 目标与设计选择

用户改完参数或算法后，应能完成：选同一套测试题 → 运行当前版本 → 对比历史基线 → 查看退化题 → 找到失败阶段。

| 方向 | 优点 | 代价 | 选择 |
| --- | --- | --- | --- |
| 独立评测应用 | 页面空间独立 | 登录、数据、历史记录需要额外关联 | 首版不选 |
| 在原运行列表增加记忆筛选 | 入口改动小 | 测试集、版本比较、阶段证据不易形成完整流程 | 适合作辅助筛选 |
| 现有评估中心内增加记忆专项 | 复用已有能力，专项流程完整 | 需要专项详情与编辑界面 | 推荐 |

沿用现有 React、Tailwind、Radix、主题、表格和状态组件。精确版本复用同日技术栈检测文档；本轮再次核对 package.json，声明范围与既有记录一致。暂不为展示方案增加组件库或图表依赖。

## 2. 入口与页面结构

位置：设置 → 评估中心 → 记忆专项。保留现有“概览、运行记录、测试集”入口；在记忆专项内部用轻量导航展示“实验记录、记忆测试集”。

六个主要视图按操作展开，不全部挤成同级标签：

| 视图 | 用户主要问题 | 主要操作 |
| --- | --- | --- |
| 实验记录 | 最近测过什么，哪个版本更好？ | 新建实验、打开报告、选择比较 |
| 记忆测试集 | 用什么题测，覆盖是否足够？ | 选择内置集、导入、编辑场景 |
| 创建实验 | 这次测哪个版本、改了什么？ | 设置候选、重复、预算、启动 |
| 实验详情 | 跑到哪里，是否完整？ | 看进度、失败原因、取消、查看报告 |
| 版本比较 | 比以前提升还是下降？ | 查看结论、分类变化、退化场景 |
| 场景回放 | 为什么这道题答错？ | 对照版本证据、逐题复核 |

创建实验和场景编辑采用内容区内的宽页面；小提示与简短操作用弹层。回放采用宽详情视图，避免在窄抽屉里阅读长对话。

## 3. 实验记录：以实验为一行

顶部为简短说明、当前基线、新建实验按钮。首次进入提供“运行内置20场景冒烟集”和“导入测试集”入口，空状态不显示虚构分数。

列表列项：实验名称、被测版本、测试集版本、测试方式、状态、可判定覆盖、主要正确率、相对基线变化、创建时间。

一次实验内部的分批任务默认折叠。用户先看到“一次完整比较”，需要排查时再展开批次。筛选支持测试集、代码版本、实验状态、测试方式；不同测试方式的分数不混成同一排名。

“设为比较基线”表示选为后续对照对象，不代表批准上线或修改生产配置。

## 4. 测试集与场景编辑

测试集卡片展示名称、场景数、问题数、版本、能力覆盖、来源及许可。首版提供20场景冒烟集、120场景核心回归集，以及外部数据导入入口。

使用大白话能力标签：事实记忆、偏好遵循、跨会话记忆、修改纠正、信息不足时不编造、遗忘、工作区隔离。训练用途之外的开发、校准、正式回归分组也应可见，避免重复调同一套题造成虚高。

场景编辑分为“发生了什么”和“应该怎么答”：

- 历史侧：按时间排列会话、纠正、换会话、重启、删除等事件。
- 判分侧：测试问题、查询时间、应记住的事实、可接受回答、禁止出现的信息、来源证据。

普通编辑用表单和时间线，原始 JSON 放入高级视图。导入失败定位到场景、字段与原因；提供修正后重试，不把内部堆栈当提示。

修改已发布集合生成新版本，不覆盖历史实验的题目和标准答案。评分标准只用于评估，不进入被测 Agent 的执行输入。

## 5. 创建实验：四步完成

1. 选测试集与范围：显示版本、能力分布、场景及问题总数。
2. 选被测版本与对照：当前配置、已保存的历史基线、可选的无持久记忆参考组；填写“这次改了什么”。
3. 选测试方式：完整记忆效果为常用入口；“是否记下来”“是否找得到”作为定位问题的专项模式。
4. 设置重复次数与预算，确认后启动。

常用字段保持简短。检索条数、阈值等放入高级设置，只展示后端实际支持且会生效的参数。不提供任意代码执行或切换历史源码的输入框。

确认区明确显示：候选数 × 场景数 × 重复次数、预计分批数量、预算上限。费用有依据才估算；无法可靠估算时标“待实际计量”，不填0元。

无持久记忆参考组仅用于完整记忆效果模式。选择历史基线时核验测试集、评分规则、重复次数和非被测条件是否一致；不一致时列出差异，限制严格比较。

不支持的产品能力应标明“当前版本不支持此项评测”，不能悄悄剔除场景。Judge未校准时说明哪些题需要人工复核。

## 6. 实验详情：进度和成绩分开

顶部显示运行状态、完成试验数/计划试验数、已判分数、消耗预算和取消操作；下面展示候选及批次进度。

单次试验按“回放历史 → 等待记忆处理 → 提问 → 评分”展示实际阶段。后台阶段可能重叠或跳过，界面按真实事件呈现，不用动画伪造完成。

运行中成绩标为临时结果。服务失败、取消、未运行、评分缺证、产品策略主动跳过分别展示。未完成计划或必要评分缺失时，总报告为“评测不完整”。

提供“只看失败”“只看待复核”“展开批次”。重试产生有来源关联的新记录，保留原失败及旧报告。

## 7. 比较报告：先结论，再原因

报告顶部固定列出基线、候选、测试集及评分版本，所有示例页面明确标记“示例数据”。主体分四层：

### 第一层：能否比较与两种结论

先显示“条件一致，可严格比较”或不一致的具体原因。

分别显示：

- 质量变化结论：有证据支持提升 / 有证据支持下降 / 尚不能确认 / 评测不完整。
- 采用建议：满足预设采用条件 / 关键项阻止采用 / 需要复核 / 未设置采用规则。

“分数升了”与“这个版本值得采用”分别判断。例如正确率提高但发生跨工作区泄漏，后者必须阻止采用。

### 第二层：四个核心信息

| 信息 | 示例 |
| --- | --- |
| 记忆回答正确率 | 基线75% → 候选85% |
| 变化量 | +10个百分点 |
| 判分覆盖 | 120/120场景，重复均完成 |
| 资源变化 | 费用和耗时分别展示，不折成质量分 |

主要正确率旁提示：“先算每个场景的成绩，再对场景取平均，避免某段长对话题多就占更大权重。”重复次数和问题数独立展示。

统计细节折叠展示差值区间、样本数及算法版本。大白话说明：“多次模拟抽样，检查这次领先是否可能只是抽样波动。”不把95%区间解释成确定的概率保证。独立样本不足时不展示区间，说明证据有限。

### 第三层：能力分项

使用可点击的对比表或横向条形图，展示能力、基线、候选、变化、覆盖与异常项。下降项优先可见，不能被总体提高隐藏。错误率下降用明确文字说明“更好”，不只按正负号着色。

抽取、检索、最终回答为不同视角，切换查看，不混算一个万能记忆总分。Agent通用指标放在单独区域，展示任务达成、约束、工具、稳定性、成本等。

### 第四层：逐场景变化

提供“变差、变好、观察结果未变、待复核”筛选，默认优先展示退化场景。每行展示题目摘要、旧/新成绩、重复结果、判定原因和回放入口。观察成绩相同不等于证明能力完全相同。

支持导出 Markdown、JSON 和 HTML 报告，导出均包含固定条件、缺失项与评分版本。

## 8. 场景回放：同一条时间线对照证据

宽屏采用左侧步骤、中间基线、右侧候选的对照方式；同一个问题与时间点对齐展示。窄屏改为按阶段排列的基线/候选切换视图。

步骤统一使用易懂名称：

1. 用户说过什么：原始历史与时间。
2. 系统记下什么：新增、更新、废弃、删除的事实及来源。
3. 系统找回什么：检索候选和筛选原因。
4. 模型实际看到什么：实际注入的证据，包含因预算被截断的部分。
5. 最后怎么回答：完整回答、预期事实、关键矛盾。
6. 为什么这样判分：规则/Judge结果、证据、人工复核记录。

例如“原来喜欢甜咖啡，后来改为无糖”：页面可标出新偏好已存储，但当前查询只找回旧偏好。结论写“本次检索未找回新偏好”，不能仅凭答错推定原因。

缺事件显示“证据缺失，无法判断该步骤”。系统只根据可观察事实定位，避免伪造模型内部推理。

人工复核针对具体问题与指标提交，显示评分版本；保存后生成新评分记录，旧比较报告保留当时快照。

## 9. 视觉与文案

沿用知序主题：主色用于选择与操作，绿色表示有证据支持的改善，红色表示退化或关键失败，琥珀色表示待复核，灰色表示未评分/不适用。颜色必须配文字或图标。

减少装饰性仪表盘，用清晰表格、并排回答、事实差异和短说明承载信息。没有数据时不显示雷达图或假趋势。

主流程使用“记没记住、找没找到、有没有用对、比上次怎样”等表达；F1、Recall@k、macro、置信区间等放在说明或高级详情。

所有指标同时可查看计算口径、样本数、来源与缺失原因。未知值显示“未评分”，不适用显示“不适用”，能力缺失显示“不支持”，零分只表示确实测得0。

表单具有清晰标签，键盘可操作；进度更新不抢焦点，错误提示靠近对应字段；宽表格在小屏允许横向滚动，长对话不用整页横向滚动。

## 10. 与原计划衔接及自检

本草案细化原WU-10的题库/创建表单和WU-11的入口/报告/回放；不在本轮改动业务代码或计划任务状态。

界面验收重点：完成导入→运行→比较→回放→复核；未完成不能假装通过；缺证不能显示0分；下降场景可见；实际配置与历史版本可查；修改题目和复核不会覆盖旧报告。

已自检：无待填章节；示例与真实成绩区分；不混合不同测试方式；统计方向和采用条件分开；界面不提供无效参数；不支持的能力不冒充已通过。当前证据为文档及现有组件静态检查，尚未制作或验证交互原型。
