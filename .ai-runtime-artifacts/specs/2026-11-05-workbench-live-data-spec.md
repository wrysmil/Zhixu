# 会话工作台：实时进展、记忆动态与技能归属

## 目标与边界

工作台以当前对话为中心，补充当前工作区记忆与可用技能。采用 A 聚焦面板的结构，结合 C 运行仪表盘的少量状态提示。继续使用黑白灰主色，只用少量冷蓝突出当前活动；不增加装饰性大图表。

本次包含前端改版、工作台接口扩展、必要的运行时观测与项目技能解析。必须让面板使用真实会话与运行时数据，不能以固定示例、回复文本猜测或文件修改时间冒充执行记录。

不改变记忆抽取策略、Dream 调度、现有记忆写入门槛，不扩建独立的记忆管理系统。本地草图仅是布局讨论素材，不作为实现的数据源。

## 已确认的设计选择

| 方向 | 优势 | 代价 | 决定 |
| --- | --- | --- | --- |
| A 聚焦面板 | 当前状态优先、适合右侧窄栏 | 需要仔细决定首屏优先级 | 采用主结构 |
| B 事件时间线 | 容易回溯完整过程 | 长会话占空间，容易与聊天重复 | 仅用于可展开的近期动态 |
| C 运行仪表盘 | 状态与运行数据醒目 | 容易堆砌数字、弱化任务内容 | 借用轻量状态与数字排版 |

用户已确认“当前对话为主，补充工作区记忆与可用技能”，并要求真实数据对接。

## 现状证据与必须补接的数据

| 内容 | 当前实现 | 本次处理 |
| --- | --- | --- |

MemoryFileStore.for_project 当前以项目路径解析记忆目录；文件是记忆本体，数据库保留检索职责。本工作台不能只读取数据库后宣称已对接新的文件记忆能力。

## 信息设计

### 进展页

首屏为当前状态卡，依次呈现：正在发生的事、任务或当前步骤、已知的运行时间。状态使用明确证据，覆盖处理中、工具运行、生成回复、等待用户、已完成、失败、中断、连接恢复中。没有细分状态来源时只显示已知的粗粒度状态，不能把等待响应猜成模型思考。

计划存在时展示已完成步数与当前步骤；进度条只表示计划完成比例，不用工具调用次数估算整个任务百分比。没有计划时显示当前活动与本轮实际产出，不制造计划或进度条。

后续按需展示计划、运行中的协作、产出与来源。近期活动最多默认展示 5 条，可展开最近 20 条；工具调用可定位到原会话活动，文件产出可预览。无记录的子 Agent、产出、来源等栏目收起，首次会话保留一处有意义的空态。

“当前轮次”由已有 turn_id / accepted turn 信息确定；旧历史缺少轮次标识时标记为会话范围，不把最近 500 条统计包装成本轮统计。普通新消息到达时切换本轮，持续目标和会话计划仍明确标为会话级。

### 记忆页

首先展示本轮可验证的记忆动态，分为：

1. 已读取笔记：成功读取允许范围内的具体笔记文件。分片读取显示“已读取片段”，完整读取才显示“已读取全文”。
2. 已写入：成功创建或修改记忆正文文件，区分新增、更新、失败；写入 MEMORY.md 目录本身单独归为目录维护，不增加笔记数量。
3. 已提供的目录：记录本轮实际注入的全局/项目目录，注明是目录而不是全文。超出注入预算或未注入的项目不能显示为已提供。

下方提供“当前工作区”“全局记忆与个人画像”的可查阅入口。目录列表是当前文件库数据，允许与本轮使用记录不同。每条笔记显示标题、描述、归属、可验证的更新时间和来源入口。个人画像只有实际注入证据时显示“已提供”，否则只是可查阅资源。

本轮统计优先按 scope + 规范化路径去重；同一笔记重复读取计为一篇，可展开查看次数。读写事件保留顺序；同一笔记既读取又修改时可在两个分组出现，但总览必须注明计数口径。

后台抽取只有能够关联到当前 session / turn 时才显示在本轮；否则作为工作区近期更新，标记“后台整理”。Dream 或其他会话改动全局文件不能冒充本轮写入。不以 mtime 推断写入者或所属会话。

工作记忆、旧数据库关联记录有明确内容且仍适用时保留在可展开的上下文区，不与文件读写事件合并计数。缺少历史观测时明确显示“历史读取记录未保留”，不能补零伪装已知。

### 能力页

技能按有效范围分为“当前工作区”“全局”；内置、插件保留独立来源分组。MCP 继续展示真实配置/连接/调用状态，CLI 保留已有真实调用信息。

“来源归属”与“使用状态”分开：来源说明来自哪里；使用状态为可用、常驻已提供、已读取、禁用、依赖未满足、被同名技能覆盖。成功读取不代表技能已执行完成。

默认展开本轮已读取的技能与当前工作区技能，全局与内置清单可折叠。显示名称与描述，路径只在来源详情中按既有权限显示。总数统计当前真正可用的有效技能；被覆盖、禁用或缺依赖的技能不计入可用数，但可在详情中解释。

## 数据与模块边界

### 统一技能解析

以 Agent workspace 作为全局技能根，当前 session 的有效 project_path 作为项目技能根。第一版沿用 Zhixu 已有 `skills/<name>/SKILL.md` 约定：项目根的 skills 为工作区技能，Agent 根的 skills 为全局技能；项目与 Agent 根相同时按同一目录去重。插件、内置沿用既有注册来源。

不把宿主 Codex 自身的技能目录当成 Zhixu 技能来源。`.agents/skills` / `.claude/skills` 等其他宿主目录不是本次默认扫描根；UI 的来源说明需要写明支持的目录约定。

优先级为项目技能 → 全局技能 → 已启用插件技能 → 内置技能。同名技能保留来源及被覆盖信息；运行时只能使用同名的有效版本。按真实路径去重，Windows 路径大小写与分隔符统一；失效路径、目录越界、循环链接不作为可用技能。

新增或扩展一个无 UI 依赖的技能目录解析器，供以下调用方共同使用：上下文技能目录、常驻技能加载、显式技能加载、工作台能力接口，以及相关子 Agent 的项目作用域解析。保持旧单 workspace 调用兼容。不以修改共享 SkillsLoader 实例的 workspace 方式切换项目，避免并发会话相互串用。

### 会话运行观测

以 session_key + turn_id + call_id 关联数据，复用现有工具生命周期与会话保存链路。需要新增的观测内容仅包括：实际注入的目录/画像范围、具体记忆文件的成功读取/修改、有效技能解析身份。记录在上下文成功组装、工具实际成功完成、后台抽取成功写入等真实边界，而不是工作台 GET 的读取过程。

单轮观测保存有界列表并记录截断标记；每轮最多 200 个事件，会话最多保留最近 20 轮。完整工具正文不复制进观测记录；只保存稳定身份、范围、状态、时间、简短描述和可授权预览的引用。事件以稳定 id 幂等合并，避免 WebSocket 重放重复计数。旧会话没有观测时允许从完整工具调用及成功结果恢复明确事件，但标记来源与覆盖范围。

读取与写入通过工具实际解析后的路径判断是否属于当前全局/项目记忆根，不能仅凭字符串包含 memory 识别。写入只在确认成功后标记；无法区别新增与更新时展示“已写入”，不能猜测新增。目录注入快照保留实际注入结果，不按当前磁盘目录重新构造历史事实。

### 工作台 API

继续使用鉴权的 `GET /api/sessions/{fullSessionKey}/workbench`，沿用会话存在性、命名空间、访问检查、no-store 和 asyncio.to_thread 查询约定。GET 保持纯查询，不创建会话、不重建索引、不触发模型、不改写笔记。

原 v1 字段保留并增加可选的 `scope`、`activity`、`memory_context`、`skill_catalog`：

| 字段 | 内容与语义 |
| --- | --- |
| scope | session、有效项目身份、当前 turn_id、观测范围与截断情况 |
| activity | 真实阶段、current_action、已知开始时间、近期事件；未知时间为 null |
| memory_context | file/database 模式、实际注入记录、read/write 事件、全局/项目目录列表及总量 |
| skill_catalog | 稳定 skill id、name、description、scope、origin、effective、availability、observed_state、覆盖关系 |

新前端兼容缺少可选字段的旧响应：显示已有真实数据与覆盖范围，不补造数据。旧客户端仍读取原字段。实现计划阶段须按上述语义落具体类型、长度限制、错误格式与并行工作单元之间的接口契约，不能由前后端独立猜字段。

目录与技能列表每组首批最多 50 条，响应包含准确总量与截断标记；提供分页读取更多，接口分页只接受固定 scope 与受限游标，不接受任意磁盘路径。既有会话列表限制继续生效；文件正文默认只在展开时按受限身份读取，摘要限制 500 字符、正文预览上限 16KiB并显示截断情况。

笔记预览需要走能够识别当前 session 可见范围的受控接口，或扩展既有预览链路。全局记忆在项目目录之外不能因此无法打开，也不能通过通用任意路径参数绕过权限。授权后的内容可以在前端既有预览容器呈现，未授权或文件已删除给出对应状态。

## 更新、故障与兼容

运行中的状态优先由既有会话事件即时更新，不等待 10 秒轮询；事件合并使用 200–350ms 防抖。持久化快照作为刷新/重连基线，活跃 10 秒、空闲 30 秒的有限轮询可保留，后台不可见或连接不可用时暂停。后台写入有会话关联时发出既有会话更新通知。

切换会话/项目必须立即隔离旧状态、取消请求并丢弃过期结果。连接断开显示状态过期或连接恢复中，不能继续把旧工具标记为确定运行。刷新同一会话失败时可保留最后成功快照，但必须标记未同步，不能把旧数据当成刚更新。

一个模块不可用只影响对应模块；鉴权错误、会话不存在、整体服务失败不能伪装成空列表。缺失不等于 0，未知时间不启动假计时，工具失败不算已读取/写入，MCP 未记录成功失败数继续使用 null。

## 视觉与交互

保留三个页签与键盘切换，默认进展。右侧默认 19rem，保持宿主拖宽能力；验证窄栏 280px、默认宽、扩宽 420px，以及移动端现有面板打开方式。标题、描述、路径均可换行或按需展开，不能挤出横向滚动。

状态卡使用细边框、轻微层次与等宽数字，不强行改站点主题。动画只用于真实活动，遵守减少动态效果偏好；完成、失败、空闲停止动画。状态同时有文字和图形，不只依赖颜色。交互控件保持可聚焦、可朗读与清晰焦点。

## 验收：必须交付数据闭环

1. 无计划的真实对话仍能随工具开始/完成/失败更新当前活动；工具结束到回复完成之间不继续显示旧工具运行。
2. update_plan 持久化后的同一份步骤只出现一次，完成比例准确；切换轮次后正确标注会话计划。
3. 临时真实文件库中放入全局与两个项目的不同笔记，通过真实上下文构建与工具读写链路验证：A 项目只能显示全局+A；失败读取不计成功；目录注入与全文读取分开；新增/更新/目录维护区分正确。
4. 外部目录的全局笔记可在授权后预览；跨项目、越界、无权限与已删除文件有明确结果。预览 GET 不创建目录或索引。
5. 后台抽取仅在有 session/turn 关联时记入本轮，其他会话与 Dream 写入不混入。重载后可恢复保留的记录，旧历史显示未记录范围。
6. 项目与全局安装同名测试技能，确认运行时真正加载项目版本，工作台也显示同一个有效身份。验证禁用、依赖缺失、插件/内置、全局根等于项目根、并发两个项目、读取同名不同路径的情况。
7. 前端覆盖加载、错误、局部不可用、重连、会话切换、旧 API 响应兼容与清单分页。统计来自真实响应与消息事件，不存在示例兜底。
8. 使用真实本地 gateway 与临时会话/文件完成接口到浏览器的集成验证，并通过确定性的真实工具调用推动状态。该验证不要求付费调用模型；若没有真实模型运行，报告明确写出这一限制，不能声称已验证完整模型行为。
9. 执行相关 Python pytest、ruff、basedpyright 与 WebUI 相关测试、构建、受影响 lint；实际浏览器验证三个页签、文件预览、状态变化和窄栏。基线失败单独记录，不绕过或静默跳过。

## 实施边界与风险

按共享数据契约拆为运行时/接口和前端两条实现工作，前端对接完成后统一集成验证。预计超过 3 个业务文件，按项目规则进入编排执行与隔离工作区；本 spec 阶段不派发实现任务。

主要风险是文件记忆的历史观测不足、并发全局文件写入归属以及固定 Agent 技能根与动态项目根的差异。通过新增有界观测、明确 session/turn 来源和统一技能解析处理，不用路径标签或时间推断替代真实运行接入。

## 自审

- 已明确可查阅、已提供目录、已读取内容、已写入的不同语义。
- 已明确 Agent 全局根与当前项目根不同，并要求运行时与界面一致。
- 已明确旧历史、未知数据、分页、局部失败、会话切换和后台整理边界。
- 已明确真实文件、真实网关、工具生命周期到浏览器的集成验收。
- 未变更记忆存储主从关系、模型策略、调度或无关界面。
- 数据结构的具体签名属于下一阶段契约与计划，行为要求在本方案中已确定。
