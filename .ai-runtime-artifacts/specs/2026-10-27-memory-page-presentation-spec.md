# 记忆页：信息层级、来源筛选与工作区筛选

## 用户目标

用户在记忆中心能读到记忆内容、来源、所属工作区和明确时间，能按来源及工作区组合筛选；编辑、详情、删除采用图标，并参考图 2 在鼠标悬停行时显示。保留当前“长期信息 / 对话记录”两类导航与自动记住总开关。

## 当前源码核查

历史记忆管理与 MEMORY.md 派生方案已查阅，但其部分内容属于旧分支，以下以当前代码为准。

| 位置 | 已确认的现状 | 本次影响 |
| --- | --- | --- |
| `MemoryListView.tsx` | 展示内容、类型、优先级、重要性、标签；未展示创建/更新时间、来源、工作区、使用次数 | 有字段未呈现，无需让模型重新生成这些数据 |
| `EpisodeListView.tsx` | 摘要下拼接会话 ID、原始开始时间、英文结果、评分，单行截断 | 时间和结果易被挤掉，需分层和中文化 |
| `EpisodeDetailPanel.tsx` | 展示目标、结果、实体、工具、动作链、关联记忆数量 | 扩充完整时间、来源、标签、会话信息，保留现有追溯信息 |
| `MemoryPayload` | 已有 `created_at/updated_at/source/workspace_id/confidence/access_count` 等 | 长期信息可增加只读详情，不把编辑窗口当详情 |
| `EpisodePayload` | 有 `source/started_at/ended_at`，无可直接用于项目筛选的工作区字段 | 需补可信工作区归属，不能从摘要猜项目 |
| `memory_api.list_memories_payload` | 查询固定使用 `services.workspace_id` | 前端下拉框本身不能实现跨项目筛选 |
| `gateway_services.py` | 记忆操作启动时绑定默认数据库与 `workspace_id="default"` | 数据库工作区与聊天选择的项目目录需明确区分 |
| `extractor._persist` | 长期信息写入 `source="extraction"`，未保留本次提取触发类型 | 历史 AI 生成记录不保证能进一步区分人工点击和后台触发 |
| `EpisodeSource` | 枚举为空闲、会话结束、上下文压缩、话题切换、整理、删除等 | 属于触发原因，不能直接映射为人工新增 |
| `MemoryEditDialog` | 支持长期信息编辑；对话记录目前只有查看、删除 | 图标分别替换已有功能，不凭空新增无契约的对话编辑入口 |

## 方案比较

1. **简洁列表＋分层元信息＋详情（推荐）**：贴近图 2，适合长内容与快速浏览；完整数据进入详情。
2. 数据表格：时间与评分便于比较，但中文长摘要导致行过高，窄屏难读。
3. 大卡片网格：视觉分组明显，但信息密度低，摘要长度差异容易造成阅读跳跃。

采用方案 1，沿用现有颜色、字体和组件体系，不复制参考图的紫色品牌样式。

## 列表展示

### 工具栏

- 来源分段：全部 / AI 生成 / 手动触发，展示各来源数量；未知历史来源额外显示“来源未记录”，不混入手动。
- 工作区下拉：全部工作区 / 默认工作区 / 已登记项目；长名称允许省略，完整路径在提示或详情中查看。
- 搜索输入保留；长期信息保留类型、优先级、排序，次级筛选放在同一筛选区，不堆叠多排大控件。
- 呈现“筛选后 N 条”；来源数量按当前工作区及关键词计算，避免切来源时其余类别数量变成 0。
- 有筛选时提供清除入口；区分“没有记忆”和“没有符合条件的记忆”。

### 长期信息行

1. 顶部：来源徽标、工作区名称、类型、优先级；标签使用轻量样式，避免全部高对比。
2. 正文：正常字重与舒适行高，最多三行；完整内容可从详情查看。
3. 底部常驻：创建 `YYYY-MM-DD HH:mm`；若修改时间不同，补充更新 `YYYY-MM-DD HH:mm`；重要性 `70%`、已引用 `N 次`，有标签时显示标签。
4. 已被替代、已过期等状态以明确文字标注，不能只依赖颜色。
5. 右侧预留详情（Eye）、编辑（Pencil）、删除（Trash2）图标区。

### 对话记录行

1. 顶部：来源徽标、工作区、结果徽标（已完成 / 部分完成 / 失败 / 进行中）。
2. 正文：优先展示已有目标为短标题，摘要最多三行；缺目标时直接展示摘要，不额外调用 AI 编标题。
3. 底部常驻：开始时间，存在有效结束时间时展示结束时间；重要性、工具数量、关联记忆数量；有实体或标签时最多展示若干项。
4. UUID 与完整会话 ID 移入详情，时间不再与会话 ID 共用截断文本。
5. 右侧保留详情、删除图标，详情读取失败可重试。

### 时间规则

- 日期和时分始终可见；不只显示“昨天”“刚刚”，不等悬停后才出现时间。
- 有时区的 ISO 时间转换为用户本地时间；详情显示秒及明确时区，保留原始值用于追溯。
- 历史无时区值不能直接追加 `Z` 假装 UTC；先核查该写入路径的约定，无法确定时标“原始记录时间，时区未记录”。
- 无效/缺失时间显示“时间未记录”；不回退到当前时间。
- 创建排序按真实创建时间；更新时间排序单独命名。现有“Recently updated”与 `order=created` 的文案不一致须修正。

## 详情与图标交互

- 长期信息补只读详情：完整内容、创建/更新/过期/最近引用时间、生成来源与触发原因、工作区、类型、优先级、重要性、置信度、引用次数、标签、主谓字段、替代关系、来源对话和可用元数据。
- 对话详情补全完整时间、来源、工作区、会话 ID、目标、摘要、结果、实体、标签、工具和动作链、关联记忆。
- 空字段显示“未记录”或省略非关键字段；来源、工作区、时间的缺失状态须明确可见。
- 鼠标设备：默认隐藏操作图标，悬停整行时淡入，行底色轻微变化；图标区保留宽度，避免正文跳动。
- 键盘：行内 `focus-within` 显示操作，按钮可 Tab 聚焦，使用有意义的 `aria-label` 和提示文字。
- 无悬停能力的触屏设备：图标常驻，不要求长按；删除仍经现有确认弹窗。
- 详情操作不触发编辑或删除；重复提交时禁用对应按钮，失败保留上下文并展示可见错误。

## 来源与工作区数据契约

### 来源

区分“内容如何产生”与“由谁触发”两个概念，避免更改生成来源后破坏审计：

- `generation_method`: `manual` / `ai` / `unknown`；现有 `manual` 可映射人工输入，`extraction` 可映射 AI 提取，`consolidation` 展示整理来源。
- `trigger_mode`: `automatic` / `manual` / `unknown`，仅有可信写入记录时赋值。
- `trigger_reason`: 保留原始空闲、上下文压缩等原因；缺失时为空。
- 用户已在本轮确认“都包含（推荐）”：“手动触发”包含人工新增与明确由用户点击触发的 AI 提取。
- AI 手动提取归入“手动触发”，行上同时标明“AI 提取”；后台 AI 提取归入“AI 生成”。旧 AI 记录只确定生成方式时展示“AI 生成 · 触发方式未记录”，不得凭现有 enum 编造人工点击历史。
- 编辑 AI 记忆后保留最初生成来源，更新时间体现编辑；如需展示“已手动编辑”，使用独立修改信息。

### 工作区

- 工作区筛选指 WebUI 中已登记的项目工作区，不把数据库的 `workspace_id=default` 直接当所有记录实际属于默认项目。
- 归属可信顺序：记录持久化的项目归属 → 明确关联的来源会话元数据 → 无归属。不得使用摘要中的路径、实体或当前聊天工作区进行推断。
- 新记录写入稳定的项目标识与当时名称/路径快照；同名目录通过完整路径或稳定 ID 区分。多项目来源的合并记忆允许多个归属，不能被最后一次编辑悄悄覆盖。
- 历史无法恢复项目归属的记录进入“工作区未记录”，始终可查。项目删除后保留历史快照，不将其改挂到默认工作区。
- 查询参数只接收受支持的工作区标识，服务端解析已登记工作区；不得接受任意磁盘路径并扫描数据库。
- 列表、搜索、来源计数、详情、编辑、删除使用同一工作区上下文与归属校验；即使不同数据库碰巧有相同记录 ID，也不可跨工作区修改。
- “全部工作区”需服务端真实聚合可访问数据及过滤后计数，不能只筛当前已加载页或当前默认数据库结果。若当前运行方式只有一个记忆数据库，先基于该库内可信项目归属筛选，并明确标示范围，不宣称已查遍其他数据库。

## 状态与一致性

- 搜索、来源、工作区、类型、优先级、排序组合生效，筛选发生在分页/截断之前。
- 清空关键词恢复列表；快速切换筛选只接受最近请求结果，防止旧响应覆盖新筛选。
- 展开 A 后迅速展开 B，不得把 A 的晚到详情显示在 B 下；关闭后不再写入失效详情。
- 编辑保存后按当前筛选刷新；记录不再满足条件时消失，计数随之更新。
- 删除成功后关闭对应详情并刷新计数；删除失败不从界面移除记录。
- 读取、详情、编辑、删除失败均有可见错误；取消操作无写入。

## 设计验收

1. 长期信息和对话记录均常驻完整日期与时分；长会话 ID 不再遮挡时间。
2. 已有重要字段有明确去处：列表负责快速判断，详情负责完整追溯。
3. 来源、关键词、工作区可组合筛选；数量与结果匹配；未知来源与工作区不会被隐藏。
4. 手动编辑不抹掉原始 AI 来源；空闲/压缩来源不会被误标为人工创建。
5. 工作区筛选覆盖真正查询层；拒绝无效工作区；读写记录归属一致。
6. 鼠标悬停显示图标、移开隐藏；键盘可操作；触屏可发现操作；删除有确认。
7. 深色与浅色、窄屏与桌面布局可读，正文与按钮不相互覆盖。
8. 增加筛选组合、时间格式/缺失、搜索清空、竞态、详情加载、修改/删除反馈等有价值的回归测试；运行相关 Python/WebUI 测试、构建、静态检查及浏览器验证。
