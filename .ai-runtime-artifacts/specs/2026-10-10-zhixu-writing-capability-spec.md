# 知序写作能力需求说明（详细版）

## 1. 背景、目标与产品边界

本需求承接「知序静态页面接入现有 WebUI」：下一步先让文章可靠保存、重开和管理素材，再让真实 AI 参与协作。文章是独立的内容对象，会话是协作过程，Agent 是执行角色，Skill 是可加载能力，这四类对象需要关联，但不能混为一体。

用户可以单独完成写作，也可以调用 AI。创作空间是通用助手中的一个工作域；通用聊天、智能体管理、Skill 管理、工具、记忆、定时任务、模型与设置入口继续保留。

本文细化需求，不构成开始实现的授权。此前「先静态页面、不要改后端」仍约束当前页面工作；下文文章持久化和真实 AI 所需的后端能力属于后续实施范围，本轮仅记录。

### 1.1 成功标准

- 用户能完成「新建 → 收集素材 → 写正文 → 保存 → 关闭 → 重开继续」完整流程。
- 多标签页、断线和 AI 生成期间的编辑，都不会被旧内容静默覆盖。
- 用户能完成「选中内容 → 发起协作 → 查看执行过程 → 对比建议 → 采纳或拒绝 → 保存」完整流程。
- 用户能查到一次协作实际使用的会话、智能体、模型和 Skill。
- 写作入口接入后，现有通用助手功能仍按原有配置与权限工作。

### 1.2 优先级

| 标记 | 含义 |
| --- | --- |
| A-P0 | 文章存储与编辑器阶段必须交付 |
| B-P0 | 真实 AI 协作阶段必须交付，依赖 A-P0 |
| P1 | 后续增强，不作为前两阶段完成条件 |

下文推荐默认值用于形成可评审需求，尚未由用户批准；具体技术实现不在本文锁定。

## 2. 当前项目依据与接入方式

### 2.1 已核对的现状

| 现有模块 | 本次代码核对结果 | 对需求的影响 |
| --- | --- | --- |
| `CreativeWorkspace.tsx` | 文章、素材、演示建议保存在组件状态中 | 需要真实存储、加载状态和保存状态；演示数据不能作为正式文章 |
| `article-model.ts` | 本地计数生成 ID；编辑时递增 revision；建议按文章 ID 与 revision 校验 | 正式 ID 要稳定且唯一；本地编辑计数与服务端版本需要拆开 |
| `creative/types.ts` | 已有正文、提纲、素材、状态和建议类型 | 延续概念，补齐真实时间、素材来源、任务关联和持久化字段 |
| `api.ts`、`agents/api.ts` | 读取使用 HTTP request，写入使用 mutation transport | 后续文章写操作沿用现有通道，不直接假定为 REST PATCH/POST |
| `nanobot-client.ts` | 已有消息发送、turn ID、工作区信息等会话能力 | 复用连接与执行事件，补文章协作适配，不在浏览器直接调用模型 |
| `nanobot/agents/runtime.py` | Agent 档案会解析提示词、模型、工具和 Skill；当前主要供子智能体执行使用 | 选择档案不等于已经能切换主会话角色，需要明确真实执行接入 |
| `nanobot/agent/skills.py` | 已有 Skill 发现、启用状态和 `$skill-name` 显式加载 | 写作 Skill 沿用既有发现与加载链 |
| `nanobot/session/manager.py` | 会话存储已有文件锁、临时文件替换等机制 | 可参考持久化习惯；文章内容仍需独立 repository 和版本检查 |

### 2.2 接入方案比较

| 方案 | 优点 | 代价 | 选择 |
| --- | --- | --- | --- |
| 文章独立存储，关联现有会话并复用执行链 | 内容、建议与任务可追溯，通用能力可复用 | 需要文章 repository、协作适配和版本校验 | 推荐 |
| 只存浏览器，前端单独请求模型 | 演示快 | 跨设备重开、版本一致性、现有工具和 Skill 难以统一 | 仅允许作缓存或演示 |
| 把文章正文作为会话历史中的最终状态 | 可借用历史存储 | 文章编辑与聊天压缩耦合，难以确定最新正文 | 不采用 |

## 3. 用户场景与主流程

### 3.1 不使用 AI 的写作

1. 从创作空间新建文章，填写标题，选择空白或现有模板。
2. 添加观点、引用文本、代码或链接，整理提纲。
3. 编辑 Markdown 正文，随时切换预览。
4. 手动保存或等待自动保存成功，看到明确保存时间。
5. 关闭页面后重开文章，恢复最近一次成功保存的正文、提纲、素材和状态。
6. 如有未同步的本地恢复稿，先对比再选择继续编辑。

### 3.2 使用 AI 协作

1. 打开文章，选中正文片段，选择「改写」并填写补充要求。
2. 检查本次使用的智能体、Skill、模型和素材范围。
3. 保存当前草稿成功后，以该版本快照发起协作。
4. 在协作区查看流式输出、工具调用和智能体活动；此时仍可继续编辑文章。
5. AI 完成后产生建议，用户查看修改前后差异。
6. 当前文章仍与请求快照一致时，可以采纳；有后续编辑时，提示建议已过期。
7. 采纳通过版本校验并持久化成功后，文章形成新版本；可以拒绝建议或重新生成。

### 3.3 冲突场景

用户在两个标签页打开同一文章。A 保存后，B 的旧版本保存被拒绝。B 保留自己的草稿，可另存副本、对比合并，或确认放弃本地修改后载入最新版本。系统不能默认按最后到达的请求覆盖文章。

## 4. 需求一：文章存储与编辑器

### A-01 文章创建与列表（A-P0）

- 标题必填，去除首尾空白后不得为空；其他字段可以为空。
- 模板只初始化提纲和写作类型，不能自动填入演示正文或 AI 建议。
- 创建成功后获得稳定文章 ID，进入编辑器；创建失败保留已填写信息。
- 列表展示标题、摘要、状态、写作类型、最近保存时间，默认按最近保存时间倒序。
- 支持按标题、摘要搜索，按状态筛选；标签用于文章标记，标签筛选为 P1。
- 空列表、加载中、读取失败、无搜索结果分别有对应提示。
- 示例文章仅在预览模式展示；正式工作区首次为空时不自动写入演示数据。

### A-02 元信息与文章生命周期（A-P0）

- 可修改标题、摘要、标签、写作类型及写作目标；目标读者、表达风格可选填，为后续 AI 提供上下文。
- 状态固定为 `idea / draft / review / done`，显示为「构思中 / 写作中 / 待校对 / 已完成」。状态由用户修改，保存或生成建议不会自动变更状态。
- 已完成文章仍可继续编辑，不因状态而锁定正文。
- 复制文章生成新 ID，复制内容、提纲和素材；素材获得新 ID，不继承协作会话、任务、建议和撤销记录。
- 删除文章前确认；若有未保存内容需明确提示。删除文章同时清理所属素材和协作结果，不默认删除关联会话历史。
- 已删除文章的晚到保存或 AI 结果不得重新创建该文章。
- 回收站和恢复删除为 P1；A-P0 不宣称删除后可恢复。

### A-03 正文编辑与预览（A-P0）

- 正文以 Markdown 为规范存储格式，支持中文、换行、列表、标题、引用、代码块和链接。
- 提供编辑、预览切换；宽屏可并排查看，窄屏切换查看，编辑内容不能因模式切换丢失。
- 编辑区支持原生撤销/重做、文本选择、复制粘贴、Tab/焦点等基本键盘操作。
- 中文输入法组合输入期间不能抢焦点、打断输入或因保存响应重置光标。
- 显示正文统计和保存时间；第一版「正文字符数」按去掉空白后的 Unicode 字符统计，标题、提纲与素材不计入，不称为精确词数。
- 内容预览复用项目 Markdown 渲染能力；链接、代码块与危险 HTML 的处理遵守现有安全规则。
- 不将富文本、多人光标或复杂排版编辑器纳入 A-P0。

### A-04 提纲管理（A-P0）

- 提纲为独立数据，支持新增、编辑、删除和调整顺序；每项有稳定 ID。
- 调整提纲不会自动重排或覆盖正文；用户需要自行修改正文，或第二阶段请求 AI 建议。
- 模板仅在新建时初始化提纲；已有文章更换写作类型不静默重置提纲。
- 提纲与正文、素材一起保存和重开。

### A-05 素材管理（A-P0）

| 类型 | 必须具备的信息 | 使用规则 |
| --- | --- | --- |
| 观点 `note` | 标题、内容 | 保存自己的观点、问题和待展开要点 |
| 文本 `text` | 标题、原文，可选来源与备注 | 区分引用原文和用户备注，AI 引用时保留出处 |
| 代码 `code` | 标题、代码，可选语言及来源 | 保留缩进和换行，不自动格式化或执行 |
| 链接 `link` | 标题、HTTP/HTTPS URL，可选摘录及备注 | 保存链接不代表已抓取或验证网页正文 |

- 支持新增、编辑、删除、排序；删除前提示，操作失败保留原有数据和输入内容。
- 素材可勾选「本次协作可用」，新素材默认勾选；保存素材不自动插入正文。
- 素材来源、备注、顺序和勾选状态随文章保存，重开后恢复。
- 同一素材可在多次协作中使用；未勾选的素材不能自动进入该次 AI 上下文。
- 链接第一版仅保存和打开，不自动抓取；真实抓取留给用户明确请求且允许使用网络工具的协作。
- 首版素材属于单篇文章；跨文章共享素材库、文件上传、批量导入和全文抓取为 P1。

### A-06 保存机制（A-P0）

- 服务端存储是正式数据来源，本地缓存只用于恢复尚未同步的编辑。
- 提供保存按钮及 `Ctrl/Cmd+S`；自动保存默认在停止编辑约 1.5 秒后触发，该值为建议默认值。
- 标题、正文、提纲、素材及其顺序等文章字段按同一个文章快照原子保存，不能出现正文新、素材旧的半保存状态。
- 同一编辑器的保存请求串行执行；编辑期间有新变化时，前一个请求完成后保存最新草稿。
- 保存响应只确认提交时的快照，不覆盖响应返回前新增的本地修改。
- 相同内容重复保存不推进 revision，也不刷新内容更新时间。
- 创建、保存和采纳支持请求标识去重；超时重试不能重复创建文章或重复应用修改。
- 只有服务端确认持久化成功，才能显示「已保存」。

| 状态 | 用户看到的提示 | 行为 |
| --- | --- | --- |
| 已保存 | 最近保存时间 | 可继续编辑、退出、协作 |
| 未保存 | 有更改待保存 | 可手动保存；自动保存等待中 |
| 保存中 | 正在保存 | 保留编辑能力，合并后续保存需求 |
| 保存失败 | 保存失败，内容已保留 | 可重试或导出，不伪装成已保存 |
| 版本冲突 | 其他位置已更新此文章 | 暂停自动保存，进入冲突处理 |
| 离线 | 无法连接，修改尚未同步 | 本地保留，恢复连接后先校验版本 |

### A-07 重开、离开与恢复（A-P0）

- 通过文章列表或含文章 ID 的入口重开，读取最新成功保存版本。
- 重开恢复正文、提纲、素材、元信息及 revision；光标与滚动位置恢复为 P1。
- 切换文章或离开创作空间时，如有待保存内容，尝试保存；失败时提供「重试 / 留在当前页 / 确认离开」。
- 浏览器刷新或关闭采用平台允许的未保存提醒；不能承诺浏览器一定拦截关闭。
- 本地恢复稿记录工作区、文章 ID、基准 revision、草稿内容及草稿时间，按范围隔离。
- 发现恢复稿时显示「恢复本地编辑 / 放弃恢复稿」；若服务端已有新版本，进入对比处理，不能自动覆盖。
- 本地缓存不可用或写入失败时，明确说明恢复保障不可用，保存与导出仍可操作。
- 读取失败不回退为演示数据；文章不存在或已删除时显示对应提示。

### A-08 版本保护与冲突处理（A-P0）

必须区分两个状态：

- `revision`：服务端成功提交的版本，单调递增；例如从 12 保存到 13。
- `local_edit_seq`：当前编辑器的本地修改计数；输入但未保存时变化，不把它当作服务端 revision。

保护规则：

1. 所有文章写操作携带 `base_revision`。服务端在同一次原子操作中校验当前版本、写内容并更新版本。
2. 标题、状态、正文、提纲、素材等持久化内容变更均推进版本；面板开关、滚动、搜索、任务进度和建议状态不推进文章版本。
3. 当版本不匹配时返回可识别的冲突错误、当前版本及读取最新内容的入口，拒绝此次写入。
4. 冲突时保留本地草稿，停止自动保存。不得自动更新 `base_revision` 后把同一份旧草稿再次发送。
5. 提供「另存副本」「查看最新版本并手动合并」「确认放弃本地修改后重新载入」。A-P0 不提供一键无条件覆盖。
6. 手动合并以最新服务端内容为基线；再次保存仍需检查版本，如期间再有更新，继续提示冲突。
7. 还原或撤销已保存操作时，写入一个新版本，不能把 revision 回拨到旧值。

示例：A 和 B 都读取版本 12；A 保存成为 13，B 以版本 12 保存被拒绝。B 保留自己的稿件，合并后以 13 为基线保存成为 14。

### A-09 导出与版本恢复范围（A-P0 / P1）

- A-P0 支持导出当前编辑稿的 Markdown，即使服务端保存失败也可导出；明确提示其中可能包含未保存修改。
- 默认导出标题、摘要和正文，不混入素材、对话、工具日志或 AI 建议；避免生成重复文章标题。
- 文件名处理空标题和不允许的文件名字符，编码使用 UTF-8。
- A-P0 的版本保护指防止错误覆盖及 AI 采纳撤销，不等于已有完整历史版本管理。
- 任意历史版本浏览、命名快照、差异比较和跨版本恢复为 P1；若增加恢复操作，仍必须产生新 revision。

## 5. 文章数据与持久化要求

### 5.1 核心对象

| 对象 | 核心字段 | 约束 |
| --- | --- | --- |
| 文章 | `id, workspace_id, title, writing_type, template_id?, status, summary, tags, brief, body, outline, materials, revision, created_at, updated_at` | ID 稳定；时间为真实时间；revision 由服务端维护 |
| 写作说明 brief | `goal?, audience?, style?` | 可为空；用于明确本篇文章目标，不修改全局助手人格 |
| 提纲项 | `id, text, order` | 与正文独立，不根据列表索引生成永久 ID |
| 素材 | `id, type, title, content, url?, source?, note?, language?, included, order, created_at, updated_at` | 属于文章；链接地址与摘录分开；复制后重新生成 ID |
| 本地草稿 | `workspace_id, article_id, base_revision, local_edit_seq, content_snapshot, cached_at` | 只做恢复，不能作为正式保存成功证明 |

字段名称用于说明语义，最终序列化风格跟随项目约定；不要把中文展示文案作为持久化枚举值，也不要保存「刚刚」等相对时间字符串。

### 5.2 存储能力

- 文章归属当前工作区，不同工作区的列表、草稿和 AI 上下文隔离。
- 文章、素材与会话历史独立存储；删除会话不删除文章，删除文章不默认删除会话。
- 成功确认后的保存应可经进程重启重新读取；原子写失败不得破坏上一份有效文章。
- JSON 文件和 SQLite 都可实现本需求，实施计划按版本检查、并发、重试去重及维护成本选择。JSON 方案必须有跨进程锁和原子替换；SQLite 方案必须有事务。
- 数据带 schema 版本，升级读取不得静默清空文章；损坏数据需显示错误并保留文件。
- 内容大小和字段数量有明确限制，在实施计划给出数值；超限不能截断后保存，也不能清空编辑内容。

### 5.3 接口能力边界

这里描述必需能力，不将建议路径当作已经存在的 API。

| 能力 | 必需输入 | 必需结果 |
| --- | --- | --- |
| 列表 / 详情读取 | 工作区范围、筛选或文章 ID | 列表摘要或完整文章；不存在、无权限、损坏可区分 |
| 创建 | 初始内容、请求 ID | 稳定文章 ID、初始 revision、保存时间 |
| 保存快照 | 文章 ID、base_revision、请求 ID、快照 | 新 revision 与提交确认；或版本冲突 |
| 复制 / 删除 | 文章 ID、base_revision、请求 ID | 新文章或删除确认；过期操作拒绝 |

读取可沿用 HTTP 路径，写入沿用现有 mutation transport；动作名、错误对象、分页和协议扩展在实施计划形成接口契约。首版素材随文章快照提交，不额外建立一组会破坏整体版本一致性的素材写接口。

## 6. 需求二：真实 AI 协作

### B-01 协作入口与动作（B-P0）

正文工具栏和协作侧栏均可发起请求；用户可填写自由指令。首版四个快捷动作：

| 动作 | 前置条件 | 输入重点 | 输出 |
| --- | --- | --- | --- |
| 改写选区 | 已选中非空正文 | 原文、周边段落、写作说明、用户要求 | 选区替换建议，保留原意 |
| 扩写段落 | 已选中段落或明确插入位置 | 段落、相关素材、需补充的内容 | 替换或插入建议，注明新增事实依据 |
| 整理提纲 | 有文章目标、正文或素材之一 | 目标、现有提纲、正文摘要、素材 | 提纲建议，不直接改正文 |
| 校对审阅 | 正文非空 | 正文、写作说明、参考素材 | 问题列表和可选局部修改建议 |

- 前置条件不满足时解释原因并保留用户指令，不静默改成另一种动作。
- 自由指令默认用于讨论和提出建议；没有明确修改目标的结果仅展示为对话，不提供不明确的采纳按钮。
- 标题摘要候选、整篇初稿、发布平台风格适配为 P1。

### B-02 上下文构建（B-P0）

- 发起前先保存当前文章；保存失败、离线或冲突时，本次协作不发送旧文章冒充最新稿件。
- 本次请求固定文章快照，记录文章 ID、base_revision、本地编辑计数、动作、选区或插入位置、用户要求、选中素材及运行配置。
- 用户能看到将使用哪些素材；未勾选素材、其他文章、无权限内容不自动发送。
- 同一任务执行期间上下文不随用户继续打字改变；要使用新内容需发起新任务。
- 长文章优先使用目标选区、必要上下文、提纲和所选素材。超过模型上下文或传输限制时提示缩小范围，不静默截断。
- 链接素材若只有 URL，需说明未包含网页正文；不能声称已读取该网页。
- 外部素材作为参考数据处理，不能将素材中的指令提升为系统指令。

### B-03 会话关联与执行复用（B-P0）

- 推荐每篇文章在首次协作时创建并绑定一个专用协作会话；创建文章本身不创建空会话。
- 一个会话只绑定一篇文章；会话显示文章标题与来源，可从创作区跳转查看完整聊天，再返回文章。
- 会话被删除时文章仍在；再次发起可创建新会话，旧任务关联显示历史会话已不可用。
- 每次协作有独立任务 ID 和 turn ID；状态、流式内容、工具、子智能体和最终建议按任务关联，不能仅按当前选中文章分配结果。
- 复用已有连接、消息总线、AgentLoop / AgentRunner、模型配置、停止、错误与执行轨迹。文章协作适配层负责上下文快照和建议转换。
- 正文的正式状态由文章 repository 管理；会话压缩不能改变文章，历史消息也不能自动覆盖最新稿。
- 同一文章首版只允许一个协作任务运行；已有任务时可查看或停止，不自动发送第二个任务。其他通用会话继续遵守项目现有并发规则。
- 需要在网关消息或 mutation 通道补充文章协作关联信息；不能假定现有 `sendMessage` 已接受文章或智能体参数。

### B-04 流式展示、停止与恢复（B-P0）

| 状态 | 展示与操作 |
| --- | --- |
| 准备中 | 校验保存、上下文、模型与 Skill；尚未进入生成 |
| 执行中 | 显示流式内容、工具和智能体状态，提供停止入口 |
| 已完成 | 展示原始回复及校验通过的建议 |
| 失败 | 显示可理解的失败原因，提供重试或调整配置 |
| 已停止 | 保留已接收文本，不把部分输出当成完整可采纳建议 |
| 连接中断 | 查询现有任务状态，不直接重发造成重复执行 |

- 完成以执行链的任务结束事件为准，不能因流式文本停止增长就判定完成。
- 停止作用于该协作任务及其相关子任务，不能停止其他通用会话。
- 重试创建新任务，使用当前已保存文章重新生成上下文；旧任务晚到结果仍属于旧任务。
- 切换文章不取消任务，结果归属原文章；文章删除后晚到结果不可应用。
- 重开文章可以查看历史任务、原始回复和建议状态；运行中任务按现有能力恢复展示，不能把本地丢失状态当作执行完成。
- 工具与模型错误沿用现有执行轨迹，不另建一套只显示旋转图标的流程。

## 7. AI 建议、采纳与撤销

### B-05 建议对象与校验（B-P0）

| 字段 | 说明 |
| --- | --- |
| `id, task_id, session_id, turn_id` | 服务端可信关联，定位本次执行 |
| `article_id, base_revision, snapshot_digest` | 定位文章和生成依据，不能由模型自行决定 |
| `target` | 正文选区、插入位置或提纲；包含定位信息 |
| `before, after, summary` | 修改前内容、建议内容和修改理由 |
| `source_material_ids, notes` | 素材依据、事实待核实点及限制 |
| `status, created_at, applied_revision?` | pending / applied / rejected / stale / reverted；状态与结果版本 |

- 建议包由模型内容与可信任务元数据组合形成；模型伪造的文章 ID、版本、来源不能成为采纳依据。
- 完整生成并校验结构、目标范围、原文一致性后，才生成可采纳建议。
- JSON 解析失败、目标缺失或正文定位不明确时，保留原始回复供阅读和复制，标记「无法自动应用」，不修改文章。
- 重复段落需按快照中的范围定位，不能用全文第一次字符串匹配替换。位置单位、换行归一化规则在接口契约中统一。
- 来源只展示本次实际使用的素材或工具返回；无法验证的事实明确标记待核实，不展示伪精确的置信度百分比。

### B-06 预览、采纳与拒绝（B-P0）

- 建议卡片显示修改理由、作用范围、修改前后内容、来源和版本状态。
- 查看、折叠、复制、拒绝建议均不改变文章；未采纳的建议不能出现在导出正文中。
- 正文替换只作用于目标选区；插入只作用于指定位置；提纲建议只改变提纲。
- 采纳前同时检查：文章 ID 一致、服务端 revision 一致、无本地未保存修改、当前目标原文与快照一致。
- 即使用户修改尚未保存、服务端版本未变，也应将旧建议标为过期。第一版采用保守规则：文章任一持久化字段在发起后有编辑，都使该任务的待采纳建议过期。
- 采纳作为原子写操作再次在服务端检查版本；按钮可点击不代表服务端无需校验。
- 持久化成功后才标记 applied，更新正文和 revision；失败时保留原文和待采纳建议，给出重试或冲突处理。
- 双击或超时重试必须去重，不能重复插入文本。
- 首版按条采纳：采纳一条形成新版本，同一旧版本下其余建议变为 stale。用户可基于新稿重新生成或手动复制；批量原子采纳与自动重定位为 P1。
- 过期建议可阅读、复制或基于最新文章重新生成，不提供跳过版本校验的强制采纳。

### B-07 撤销采纳（B-P0）

- 支持撤销最近一次已成功采纳操作，保存该操作前的内容及采纳后的版本。
- 仅在当前服务端版本仍为该采纳结果版本，且没有后续本地修改时可撤销；存在其他编辑或保存时禁用并解释原因。
- 撤销也要版本校验并原子保存，产生一个新 revision；不能恢复旧 revision 数值。
- 撤销成功将建议标为 reverted，旧建议不能重新变成可直接采纳状态；再生成需使用新版本。
- 撤销保护信息持久化，重开后仍可在满足条件时撤销。正文编辑器的原生撤销/重做与此业务操作分开处理。
- 示例：版本 12 采纳成为 13；无后续编辑时撤销成为 14，正文恢复到采纳前。版本号不会从 13 回到 12。

## 8. 写作智能体与 Skill

### B-08 写作智能体档案（B-P0）

- 复用现有 AgentProfile，新建或复用合适的写作预置，不修改通用默认助手。
- 在智能体管理中可查看、编辑、复制和恢复预置配置，沿用现有名称、描述、提示词、模型、工具、Skill 和子智能体配置。
- 创作空间默认选择写作智能体，也允许用户选择具有相应能力的其他智能体；选择只影响本篇协作，不修改全局默认配置。
- 发起请求前展示实际智能体和模型；未指定模型时继承项目有效默认配置。
- 档案必须真实作用于执行：提示词、模型及工具/Skill 裁剪都按现有运行时解析，不能只改变 UI 标签。
- 当前档案运行时主要用于子智能体，推荐通过现有通用会话协调指定写作子智能体；若现有调用入口不足，实施计划需补最小适配与模型解析接入。仅写一段「请扮演写作助手」不算完成。
- 每次任务固定当时有效的配置，运行中编辑档案不改变该任务；下次发起时重新解析配置。
- 默认写作档案不开放文件写入、命令执行和发布等非必要操作；网络或研究工具按配置显式允许，沿用既有权限边界。
- 写作职责包括保持原意与个人表达、区分事实和推测、依据素材说明修改，不替用户采纳、保存或发布。

### B-09 写作 Skill（B-P0）

| Skill | 首版用途 | 必须说明的输出边界 |
| --- | --- | --- |
| `article-rewrite` | 改写选区 | 保持原意，输出指定范围替换建议 |
| `article-expand` | 扩写段落 | 区分素材事实和新增推测，标出依据 |
| `article-outline` | 整理提纲 | 输出结构建议，不直接覆盖正文 |
| `article-review` | 校对审阅 | 输出问题、理由及可选局部建议 |
| `article-title-summary` | 标题和摘要候选，P1 | 候选由用户选择，不自动改标题 |

- 以普通 `SKILL.md` 进入现有 Skill 目录与加载机制，不在前端硬编码成另一套提示词库。
- 每项 Skill 明确用途、输入、步骤、输出格式、适用范围和不应执行的操作；可以附参考文件，不默认常驻所有会话。
- 快捷动作映射对应 Skill；显示推荐项，用户可更换或禁用，但不支持在禁用后静默假装该 Skill 已使用。
- 发起时校验实际存在、已启用且被所选 Agent 允许；不满足时说明原因，允许调整配置或显式改用普通讨论。
- 沿用现有 `$skill-name` 显式调用能力，写作 Skill 在通用聊天中同样可使用；没有文章上下文时通过对话收集必要输入。
- 执行记录区分推荐、选择、实际加载和加载失败；若缺少实际加载事件，需在现有轨迹上补充最小证据。
- Skill 被禁用、删除或工作区同名覆盖时，沿用现有发现优先级和启用语义；不能由创作区自动重新安装或改全局设置。

### B-10 通用能力兼容（B-P0）

- 聊天仍支持自由指令、工具、Skill、子智能体、长期任务等既有能力。
- 智能体与 Skill 管理保留全部类型，写作只新增分类和使用入口，不替换现有列表。
- 模型、连接、权限、工作区和设置仍只有一个配置来源，不出现「聊天已配置、写作还要重新填密钥」。
- 文章默认不通过新增写作流程主动写入全局长期记忆；用户主动要求记住的偏好沿用现有机制。
- 关联协作会话是否被现有 Dream 自动处理，需在实施前核对并明确策略；产品不能在未隔离现有记忆链时声称文章绝不进入记忆。
- 文章协作标记用于限制自动记忆提取范围，首版验收要覆盖正文与素材不被自动提取进全局记忆；完整文章知识库另作需求。
- 现有记忆管理、自动化、工具和其他设置的访问方式及实际操作需纳入兼容验收。

## 9. 页面与交互要求

- 创作列表页承接文章创建、搜索、状态筛选和最近编辑；编辑页承接正文、素材/提纲和协作建议。
- 沿用当前知序整体页面风格、组件与主题，保存状态、空态、错误态和弹窗统一。
- 编辑页顶部显示文章标题、状态、保存状态、导出及返回；窄屏优先保证编辑和保存操作可见。
- 素材/提纲与协作区可折叠；切换面板不会清空输入或终止任务。
- AI 建议区别于正式正文；执行中的流式回复区别于已完成、可采纳的修改。
- 冲突和过期提示直接说明「文章已更新，需要合并/重新生成」，无需用户理解内部版本字段。
- 保存、预览、素材操作、发起协作、停止和采纳均可通过键盘访问，有清晰焦点与可读标签。
- 沿用现有国际化和主题机制，新文字不得散落成不可翻译的硬编码；深浅色主题下状态和差异都可辨识。

## 10. 失败处理与非功能要求

| 场景 | 必须行为 |
| --- | --- |
| 保存超时但可能已提交 | 按请求 ID 查询/重试确认，不盲目重复提交或覆盖 |
| 服务端更新、本地仍有草稿 | 提示冲突，保留两份内容 |
| 存储满或文件写入失败 | 不显示成功，不破坏上一有效版本 |
| AI 运行时用户继续编辑 | 保留新编辑，旧建议过期 |
| AI 返回格式错误 | 保留原始回复，禁止自动应用 |
| 停止后仍有晚到事件 | 显示为旧任务数据，不恢复采纳权限 |
| 智能体、模型或 Skill 不可用 | 发起前或执行中给出具体原因，不偷偷更换配置 |
| 会话删除或文章删除 | 按各自生命周期处理，不相互误删或重建 |
| 任务连接中断、页面重开 | 查询状态，不自动启动第二次执行 |

- 内容保存与建议应用要求原子性；并发校验不能只在前端做。
- 编辑输入不等待网络，列表读取不返回所有完整正文；分页方式在接口契约中明确。
- 身份验证、工作区访问和 WebUI 写入权限沿用项目机制，不能新增绕过鉴权的写作入口。
- 日志记录任务标识、版本、状态和失败原因，避免默认记录整篇正文、素材和凭据。
- Markdown 与模型输出统一按不可信内容渲染，不执行其中的脚本或代码。
- 单用户、多标签页是首版并发模型；不承诺多人实时协同。

## 11. 验收场景

### 11.1 文章阶段

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| A-T01 | 新建文章，刷新并重启服务 | ID 稳定，成功保存内容可读取 |
| A-T02 | 修改正文、提纲、素材及排序后重开 | 所有字段与最后成功快照一致 |
| A-T03 | 保存过程中继续输入 | 响应不覆盖新输入，最终保存最新稿 |
| A-T04 | 中文组合输入、代码粘贴、切预览 | 输入与缩进保留，光标不因响应跳回 |
| A-T05 | 重复点击保存、超时重试创建 | 不重复建稿，相同保存不重复推进版本 |
| A-T06 | 两个标签页以同一版本保存 | 后提交者冲突，本地内容保留 |
| A-T07 | 冲突后另存或手动合并 | 原稿不被无条件覆盖；新保存继续校验版本 |
| A-T08 | 离线编辑后重开，服务端已有新稿 | 恢复稿先对比，不自动覆盖 |
| A-T09 | 保存失败、缓存不可用 | 说明限制，编辑内容仍可复制和导出 |
| A-T10 | 复制、删除及晚到保存 | 副本 ID 独立；删除后旧请求不复活文章 |
| A-T11 | 切换工作区、从正式入口首次进入 | 数据隔离，演示文章不混入正式列表 |
| A-T12 | 导出带未保存修改的 Markdown | 与当前编辑稿一致，含明确提示，无协作日志 |

### 11.2 AI 阶段

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| B-T01 | 发起四类快捷协作 | 使用已保存快照和对应输入，产生真实任务 |
| B-T02 | 改变智能体提示词、模型和工具范围后协作 | 实际运行配置生效，轨迹可核对 |
| B-T03 | 选择、禁用或删除写作 Skill | 实际加载可追溯；不可用时不伪装成功 |
| B-T04 | 勾选部分素材发起请求 | 只有所选素材进入上下文，来源可查 |
| B-T05 | AI 生成时修改文章但不保存 | 旧建议不能采纳，新编辑不丢失 |
| B-T06 | 另一个标签页保存后采纳 | 服务端拒绝过期采纳，不只依赖前端按钮 |
| B-T07 | 预览、拒绝、复制与单条采纳 | 前三者不改文；采纳只改目标且产生新版本 |
| B-T08 | 双击采纳、超时重试 | 修改只应用一次，建议与文章结果一致 |
| B-T09 | 采纳后撤销；后续又编辑再撤销 | 无后续编辑时产生新版本恢复；有编辑时拒绝 |
| B-T10 | 格式错误、重复段落、停止后部分输出 | 不误定位、不自动套用不完整输出 |
| B-T11 | 切文章、断线重开、删除关联会话 | 任务仍归原文章，不重复启动，文章可继续编辑 |
| B-T12 | 通用聊天、工具、Agent、Skill、记忆与设置回归 | 保留既有功能和全局默认配置 |
| B-T13 | 检查协作会话的自动记忆处理 | 正文与素材不被自动提取为全局长期记忆 |

验收证据需覆盖前端交互、后端并发和持久化，以及至少一次真实模型协作。测试替身可验证事件与错误流程，但不能代替真实 AI 接入验收。
