# 知序记忆评测平台与 Agent 指标规范

## 1. 要解决的问题

开发者今天调整检索参数，明天改抽取或冲突合并算法，能对同一组任务重复测试，知道整体与各类场景提升、退化或证据不足，并能定位到写入、更新、检索、注入、使用中的具体环节。

成功交付的核心是一份可追溯的版本对比报告：变更内容、固定条件、能力分项、逐题变化、成本与延迟、缺失证据、重复实验和不确定性。平台界面用于管理这套实验，而界面本身不构成记忆能力证据。

首版用户：知序开发者，本地单用户评估。首版范围经用户确认：事实/偏好、跨会话、纠正、时间有效性、遗忘与隔离。经验记忆对后续任务执行的收益为第二阶段。

本轮交付方案、指标字典、数据格式示例与开源选型；未实现平台或运行质量评测。本文指标是本项目拟采用的统一口径，借鉴公开评测方法，不声称存在适用于所有 Agent 的唯一行业标准。

## 2. 方案比较与选择

| 方案 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| A. 扩展现有知序评估平台，接入基准与专项执行器 | 复用集合、Worker、Trace、规则/Judge、重复实验、配对比较、现有页面；测试真实记忆链路 | 补跨会话协议、状态屏障、结构化记忆证据与专项评分 | 推荐 |
| B. 直接以 MemEval 为主体，编写知序 adapter | 较快对接现有基准与其他记忆后端 | 产品专项、现有评分/人工复核/页面仍需适配，两套运行历史并存 | 可作外部交叉验证工具 |
| C. 以 Langfuse / Phoenix 等完整平台为主体 | 已有协作标注、实验与可观测性界面 | 引入部署和数据迁移；仍需实现知序写入、跨会话、删除等执行协议 | 团队协作规模扩大再考虑 |

推荐组合：A + LongMemEval 首个外部 loader + 中文产品专项集；借鉴 MemEval adapter，DeepEval/Ragas 作为可替换评分插件，Langfuse 作为可选导出目的地。首版不同时引入多个后台服务，不整体迁移已有评估记录。

## 3. 评测结构：通用层与记忆专项层

```mermaid
flowchart LR
    D[版本化测试集] --> E[实验配置与版本快照]
    E --> W[隔离场景执行器]
    W --> P[写入历史并结束会话]
    P --> B[等待记忆与索引处理结果]
    B --> Q[新会话提问或执行更新与删除]
    Q --> T[阶段事件与状态快照]
    T --> G[规则评分与校准后的语义评分]
    G --> C[场景配对与分类对比]
    C --> R[报告和失败回放]
```

首版提供三条测试路径，报告明确标注路径，禁止混算：

| 路径 | 输入与操作 | 能回答的问题 |
| --- | --- | --- |
| extraction | 固定历史 → 真实抽取/更新 → 对照期望原子事实 | 是否应该记、是否记对、是否合并正确 |
| retrieval | 导入经过校验的标准记忆状态 → 固定查询 → 观察召回与注入 | 检索与重排参数变化是否有效；不测抽取 |
| end_to_end | 原始历史 → 真实记忆处理 → 开新会话 → 真实 Agent 回答 | 用户最终得到的记忆能力是否改善 |

检索专项使用标准状态，端到端必须让基线与候选分别从相同空状态建立自己的记忆，不能把基线抽取后的库直接给候选并声称测了新算法全链路。

## 4. 场景执行协议

1. 每个“候选×场景×重复”独立数据根、session、workspace、画像、工作记忆、SQLite、向量集合和缓存命名空间。默认禁用网络搜索与日常工作区文件访问，避免从其他通路找到答案。
2. 按事件顺序重放多次历史会话；保留用户与助手身份、来源、时间、作用域。抽取专项可直接导入固定 transcript；端到端路径必须经过产品等价的会话结束处理，不用旧 memory_seed 代替。
3. 会话结束后等待明确处理结果：抽取、落库、索引可见均可查询，且区分 completed / skipped_by_policy / failed。达到上限后记为处理超时，不使用“睡几秒”充当成功。
4. 跳过是可观测的产品策略：短会话未达到抽取条件也要报告；场景若要求记住，该状态可以导致能力未达预期，不能一律剔除为基础设施问题。
5. 查询换新 session，清空会话短期历史，只携带按产品策略允许持久化的状态。重启子集重新加载磁盘状态，验证持久化。查询前检查实际模型上下文，确保没有偷偷携带原始全历史或标准答案。
6. 时间测试记录 Asia/Shanghai 与明确时间戳，区分事件发生时间、生效时间、查询时间；向衰减、TTL、抽取和幂等等相关组件注入同一测试时钟。未覆盖的时钟依赖显式报“不支持”，不假装模拟过了一天。
7. 同一场景多次探测默认从该检查点复制状态，每次探测新 session；禁止前一次查询和回答污染后一道题。需要测连续使用的场景单独标明有序协议。
8. 记录失败阶段并可取消；setup、模型服务异常、执行超时、评分失败分开保存。重试是同一 trial 的新 attempt，保留历史与成本，不以挑选最好答案代替一次测量。

首版 adapter 的逻辑能力为 reset、ingest_session、settle、snapshot、recall、answer、apply_update、forget、close。它们是待实现的能力边界，不是已经存在的 SDK 方法。只有支持的操作才能计分；不支持的项标记 capability_missing，不静默通过。具体 API/数据库契约在实施计划前定义。

## 5. 测试集合与导入

需要统一测试集合，且首版平台内置默认集合，用户可以直接运行，也能导入 JSON/JSONL。界面编辑器生成同一格式；不要求用户先自己编完整题库。

每条不是孤立的“问题—答案”，而是包含历史、会话边界、状态变化、探测问题、证据及期望状态的 scenario。公共 case ID 永久稳定；内容变更生成 revision。每个集合包含 schema_version、dataset_version、来源、许可、split、hash 和评分配置。

| 测试集 | 初始规模建议 | 运行方式 |
| --- | --- | --- |
| 中文冒烟集 | 20个独立场景 | 开发时单次，快速发现明显问题，不代表整体质量 |
| 中文核心回归集 | 120个独立场景，10类各12个 | 发布候选重复3次，场景级聚合 |
| LongMemEval | 开发时固定分层子集，里程碑评测使用完整500题 | 保留官方数据版本、题型、Judge协议；样本成绩不冒充全量成绩 |
| LoCoMo / MemoryAgentBench | 后续按预算选择 | 单独报告；先确认数据用途和许可 |

10类专项：稳定事实、偏好约束、同义问法、时间有效性、知识纠正、多会话综合、信息不足拒答、无关信息干扰、明确遗忘、工作区/身份隔离。每类包含正例和适用的反例；偏好包括“只偏好不禁止”和“明确禁止”的区别，隔离包括允许共享的正例。

重复和题目总数需受预算约束：当前单 run 最多200 attempts，120×3=360，必须先使用 experiment_group 分成例如3批40场景×3次并聚合，或经明确设计后扩展上限；不能创建失败后偷偷减少重复次数。长历史使用专项事件流，不破坏原 turns<=20 的旧数据契约。500题全量也必须分批。

数据分为开发/调参集、Judge校准集、保留回归集。相同人物/对话/事件模板不能横跨 split；由真实失败脱敏补入的 case 生成新集合版本，新增版本不能直接与旧集合总分比较。公开基准可能被基础模型见过，加入新构造的虚构事实和新实体降低背题影响，不能宣称完全消除污染。

以下为拟议的 memory-scenario/v1 示例，仅说明数据语义，当前导入器尚不支持。gold 区只交给评估端，不放到 Agent 可读路径或上下文中。

## 6. Agent 通用指标字典

通用层复用 task / constraints / trajectory / efficiency / safety 五维。以下作为标准化输出字段的语义；实现时保留既有字段兼容映射，不静默改旧报表分母。

| 指标 | 定义/分母 | 方法与说明 |
| --- | --- | --- |
| 任务成功率 | 完成全部必需任务目标的已判定试验 / 已判定试验 | 规则或锚定量表；另报成功/计划数作为端到端交付率 |
| 任务完成度 | 完成里程碑权重之和 / 所有适用里程碑权重 | 部分完成不能与完全成功混淆；缺材料记未知 |
| 约束遵循率 | 所有必需约束通过的试验 / 可判定试验 | 输出格式、禁止操作、用户限制分别检查 |
| 工具决策正确率 | 工具选择与参数均正确的标注决策点 / 可判定决策点 | 分报选工具与参数；包含“应不调用工具”；不能用工具调用成功率代替 |
| 工具执行成功率 | 成功执行的调用 / 有执行结果的调用 | 衡量执行可靠性，不证明决策正确 |
| 回答质量 | 各维度0–4锚定量表及其分布 | 正确、相关、充分、证据支持分别报告；规则可评分时优先规则 |
| 过程违规率 | 出现禁止动作/跳过必要验证的试验 / 可观察试验 | 允许多种正确路径，不强制模仿唯一工具轨迹 |
| 重复稳定性 | 同场景k次全部成功的场景数 / 完成全部k次且可判定的场景数 | 同时显示每场景平均成功率、至少一次成功率、重复覆盖；不冒称同一个pass@k指标 |
| 延迟 | 单次完成耗时p50/p95；超时另列 | 生成、工具、记忆后台处理分段；展示样本数和硬件条件 |
| 资源成本 | 输入/输出Token、嵌入量、模型请求、实际/估算费用 | Agent与Judge分开，缓存命中另报；未知费用为null，不能填0 |
| 安全边界违规率 | 至少一次越界的试验 / 可判定安全试验 | 越权读取、禁止工具等；若不可观察则不判“安全” |
| 评测覆盖与运行健康 | 可判定数/计划数；各技术失败数/计划数 | 同时显示取消、未运行、服务失败、评分失败、待人工复核 |

当前 reports.py 的 task_success_rate 使用 completed/planned，属于交付口径。新增条件成功率需用明确新字段或展示标签，旧含义保持；比较时固定 coverage 条件，避免排除失败样本后“变好”。

## 7. 记忆专项指标字典

期望记忆标注为原子事实：主体、属性、值、作用域、时间有效区间、来源与状态；按同一版本的语义匹配规则做一对一匹配，重复存储不能重复计TP。

| 环节 | 指标 | 定义与注意事项 |
| --- | --- | --- |
| 写入 | 抽取Precision / Recall / F1 | P=TP/(TP+FP)，R=TP/(TP+FN)，F1=2PR/(P+R)；只对该检查点应保留事实计分；区分幻觉、重复、作用域/时态错误 |
| 写入 | 无依据记忆率 | 没有历史来源支持的新增原子事实 / 全部新增原子事实；避免系统把推测当用户事实 |
| 更新 | 最新有效事实正确率 | 更新探测中正确使用查询时有效事实的题数 / 可判定更新题数 |
| 更新 | 过期事实误用率 | 要求当前状态的查询中把旧值当当前值的题数 / 可判定当前状态更新题数；“提到旧值”本身不算误用 |
| 检索 | Evidence Recall@k | top-k去重证据覆盖的gold证据单元 / gold证据单元；以来源turn/原子事实对齐，不依赖不同算法的随机memory_id |
| 检索 | Precision@k / MRR | top-k有效相关结果比例（分母为实际返回条数并同时报返回数）；首条相关结果倒数排名；无相关gold题不算召回分 |
| 注入 | 必要证据注入覆盖 | 实际送入模型的上下文覆盖的gold证据 / 所需gold证据；检查所有记忆来源，不只看一次召回结果 |
| 使用 | 记忆问答正确率 | 满足答案与时态/作用域条件的可判定探测题 / 全部可判定探测题；另报完整场景全通过率 |
| 使用 | 偏好遵循率 | 在应适用偏好的任务中正确应用偏好的题数 / 可判定偏好题数；正向选择和明确禁忌分报 |
| 使用 | 无依据回答率 / 正确拒答率 | 无答案题中编造个人事实的比例 / 正确承认信息不足的比例；另报有答案却拒答率，防止全拒答刷分 |
| 持久化 | 跨会话/重启保持率 | 换session/重启后正确的题数 / 对应可判定题数；按间隔、干扰量与状态加载方式分层 |
| 遗忘 | 行为遗忘成功率 | 请求删除后所有同义/旁路探测均未暴露目标事实的场景 / 可判定删除场景；拒答文本不能代替存储检查 |
| 遗忘 | 状态删除完整率 | 声明的删除范围内所有活动存储/索引/缓存均达要求且重建后未复活的场景 / 可判定删除场景 |
| 隔离 | 跨作用域泄漏率 | 在检索候选、最终注入或回答任一阶段出现禁止事实的场景 / 可观察隔离场景；分别记录发生阶段 |
| 效率 | 写入/索引/召回/注入延迟与成本 | 分阶段p50/p95、Token、嵌入、存储字节；共享写入成本按原始conversation记一次，摊销另列 |
| 净收益 | Memory Lift | 相同生成模型下有记忆与无持久记忆的配对正确率差（百分点）；按任务与预算分层，不代表全部归因已被证明 |

集合同时报告题级micro与场景/类别macro，并显示各自样本数；主要版本结论用场景macro，避免一个长对话拥有很多题就主导总分。TP/FP/FN全为零时标不适用；P/R分母为零各自记null，F1只在有定义时计算；纯负例另报“不应记却写入”的场景比例。

有多组等价证据时，标注可替代证据组与多跳所需证据集合；报告中区分“命中任一证据”和“证据集齐全”。知识合并后按来源/原子语义匹配，不要求候选复现基线的分块方式。针对可导出state的路径才计算状态指标，黑盒后端不支持时只报行为指标与覆盖缺口。

遗忘首版协议先声明范围：目标事实应退出可检索活动记忆及派生索引、画像、scratchpad、缓存；受限审计记录是否保留、原会话是否允许检索由删除策略明确。若原历史保留，必须有墓碑/重建抑制，不能下一次Dream又写回。物理备份永久擦除不属于首版能力，也不能用行为测试宣称完成。

身份隔离在本地使用合成身份及既有workspace边界；若产品没有user/tenant层授权，报告明确“身份隔离能力未提供”，不能凭传入subject_id就声称多租户安全。允许共享的记忆必须有正例，防止“什么也不返回”被当成隔离正确。

## 8. 版本比较：判断今天的变更是否有效

每次实验冻结四组条件：

- 数据：集合revision、split、场景/probe IDs、顺序、抽样清单、来源hash。
- 候选：Git SHA与脏文件摘要、抽取/合并/Dream策略、检索通道与权重/top-k/阈值/预算、prompt、生成与抽取模型、embedding/索引参数及后端版本。
- 环境：隔离状态起点、时钟协议、模型模式、工具能力、硬件/并发、超时、缓存冷暖规则。
- 评分：规则版本、量表、Judge模型/提示词/参数、gold与校准集版本、已声明的主要指标和容忍度。

comparison模式显式声明被测变量：只改rerank权重、只改抽取算法，或整体memory-stack变更。允许变化的参数放candidate摘要，其他字段必须匹配；不能把被测参数放environment后导致所有合法实验不可比较，也不能允许未声明模型变化后把分数差都归因于记忆。

基线从必需的三组开始：无持久记忆（查询历史同样清空）、当前知序、候选知序；原始历史BM25/向量RAG作为简单参考组逐步加入；full-context仅在容量允许时作诊断参考。需要隔离reader影响时固定同一个reader及预算，另做端到端轨道；不把两个轨道混合排名。

配对以同scenario/revision比较，先聚合重复，再按原始conversation或scenario聚类bootstrap得到差值95%区间。沿用当前“少于20个独立配对只描述差值”的显示策略；20个不是统计充分性的保证。区间跨0或覆盖不足时显示“尚不能确认”，不是持平证明；大范围筛选参数另用保留集复验，避免调参过拟合。

拟议发布规则（项目建议，需基线实测后定值，不是行业阈值）：

1. 先满足协议完整、计划试验完成及关键指标可评分；技术缺失时状态为“评测不完整”，不得显示质量通过。
2. 任一确认的跨作用域泄漏、明确删除后复活，均阻止该候选进入下一阶段；样本0次违规只说明本集未观察到违规。
3. 主要指标预先选“端到端场景macro正确率”；增益区间下界>0才标记统计支持提升，点估计单独显示。
4. 纠正、拒答、遗忘、隔离分项不被总体均分抵消。非关键项的退化容忍度与预算上限在实验前设定；未设阈值时仅出诊断报告，不自动放行。
5. 延迟/成本变好但质量下降时展示权衡；与质量改善一起报告，不包装成单一“提升百分比”。

示意：候选从80%到84%表示+4个百分点；如果更新题从90%到75%，报告必须列出这些退化场景。该数字仅示例，不是本项目测量。

## 9. 评分可信度与证据

优先级：结构化状态/确定规则 → 语义事实对齐 → 经过校准的Judge → 人工复核。禁止用“答案包含无糖”这样的弱断言单独证明偏好更新正确，因为回答可能同时推荐了已失效选项。

语义评分为0–4锚点：0错误或编造；1仅少量相关；2部分正确但关键事实缺失/冲突；3关键事实正确且约束满足；4完整正确且有可核验证据。必须逐维给证据，不把无引用回答一概判0；若产品未要求输出引用，用内部事实来源核验支持度。

Judge只读隔离评分材料、没有工具执行权限；历史文本/回答中的指令仅当数据处理。材料含完整问题、查询时点、作用域、参考事实与关键证据，长度不足时标记材料截断。A/B匿名并随机顺序，避免偏爱某个版本；Judge模型、prompt和gold变更后不能直接延续旧分数。

先用独立人工标注的校准集验证：分类一致率、混淆矩阵、错误放行率与错误拒绝率，必要时Cohen's kappa；类别不均衡时不只看一致率。确认阈值前语义分数带“实验性/待复核”，不作为唯一发布门槛。不能把当前平台已有校准模块等同于校准已合格。

每个metric记录id/version、分子/分母、值、状态、适用场景、证据引用、缺失原因、置信区间（若适用）。缺材料为not_assessable，不填0，也不默认为成功。

## 10. 平台需要的页面与持久化资产

| 功能 | 用户能完成的操作 | 必须看到的证据 |
| --- | --- | --- |
| 测试集 | 选内置集、导入、检查格式、编辑版本、查看覆盖分布 | 场景历史、时间线、gold、split、来源和许可；gold仅评估端可见 |
| 实验 | 选baseline/candidate、声明变更、设预算、启动/取消、分批进度 | 真实生效配置、试验数、模型模式、记忆后端、状态屏障 |
| 比较报告 | 看分类差值、成本、区间、改善/退化清单 | 严格可比性判定、排除样本与原因、覆盖率 |
| 场景回放 | 展开历史 → 抽取 → 状态变化 → 召回 → 注入 → 回答 | 来源对齐、原始与有效事实、筛选原因、上下文预算、失败阶段 |
| 评分复核 | 复算规则、审阅Judge、提交人工判定 | 评分版本、校准状态、证据与复核记录；更改后保留旧结果 |

数据实体扩展：DatasetRevision、MemoryScenario、Probe、ExperimentGroup、CandidateSnapshot、Trial、MemoryEvent、StateSnapshot、MetricResult、Comparison。复用原case/run/attempt/trace和artifact标识，避免第二套互不关联的历史。指标用扩展表/有版本的子结构，旧报告继续可读。

记忆事件至少覆盖：session_closed、extraction_completed/skipped/failed、memory_added/updated/superseded/deleted、index_ready、recall_candidates、reranked、injected、answer、grade。保留调用路径、耗时、scope、来源ID、state版本及原因；最终注入证据以实际上下文为准，不能由预期召回结果推算。

运行产物保留内容摘要与脱敏元信息，密钥不入manifest；文件/数据库在评估隔离数据根，用户日常记忆只读也不默认挂载。真实用户日志进入题库前先脱敏，禁止直接上传外部平台。AI过程文档仍只放.ai-runtime-artifacts，对测试运行数据沿用产品自己的隔离存储约定。

## 11. 分阶段交付边界与验收

第一阶段专注本地可重复回归：统一场景协议、三条测试路径、中文冒烟/核心集、LongMemEval loader、记忆事件、指标与比较报告。先覆盖产品支持的workspace边界；外部memory backend、跨租户安全、多服务部署不强塞首版。

验收必须能演示：

- 同一集合对当前/候选运行，报告显示全部固定条件与真实被测参数。
- 人为构造抽取漏项、检索漏召回、注入截断、回答误用四类问题，分别定位到对应阶段，而不是都叫“回答失败”。
- 纠正后按当前状态回答、按过去时间回答各自正确；无信息时拒答，有信息时不滥拒答。
- 换session及重启后读取正确；更新/删除后索引一致；删除重建不复活；禁止workspace信息在召回阶段也不泄漏。
- 不支持的能力、缺失证据、服务错误、未完成重复都能使报告明确显示不完整。
- 受控脚本可验证平台统计与断言链路；真实模型单独验证记忆质量，报告不将两者混淆。
- 120×3和500题分批运行可聚合且不重复记账；旧Agent测试集/报告保持可读。

第二阶段单独设计：经验记忆、任务反馈后学习、增量冲突与长时程干扰曲线；选择MemoryAgentBench、LongMemEval-V2与受控真实任务；MemoryArena先做适配成本与许可核查。衡量实际任务成功率变化和负迁移，不仅问答记住了多少。

这不是已拆分的编码计划。进入实施计划时再给出数据契约、迁移策略、文件边界和验收任务；不在本轮创建代码骨架或修改现有记忆算法。
