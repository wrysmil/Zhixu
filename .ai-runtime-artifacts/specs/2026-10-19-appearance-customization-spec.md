# 知序全局外观自定义方案

## 1. 目标与范围

在现有「设置 → 外观」内提供预设主题、自定义强调色/背景色/文字色、字体设置。保持参考图的横向设置行、分组容器和明确层级，结合知序现有设置组件实现。用户修改后立即看到真实界面变化，刷新及同一来源下重启后保留。

用户已选择「全局外观：预设主题 + 自定义颜色 + 字体（推荐）」，随后单独回复「直接实现把」，批准本方案并授权直接实现。根据 dispatcher 输入规则采用 skip:plan 路径，以本方案、接口契约和执行图组织工作，不另开计划确认阶段。

覆盖 WebUI 与桌面端内的 WebUI，包括首页、聊天、侧栏、设置、Agent/Teams 页面及编辑弹窗、记忆页、工作台。品牌图片、用户上传内容、Agent 身份色、状态语义色与代码语法分类色保留各自含义；终端基础背景、前景和代码字体跟随主题。嵌入的第三方网页不受本应用样式控制。

首期不包含主题文件导入导出、云同步、任意 CSS 编辑、字体下载/上传、系统字体枚举、TUI 或操作系统原生标题栏改色。字号和行距不增加新设置，避免把字体选择扩大为全套排版编辑器。

## 2. 方案选择

| 方案 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| 扩展现有 CSS 语义变量，由主题配置统一派生 | 延续现有组件，能覆盖全局，主题数据集中 | 需适配少量硬编码页面和独立渲染器 | 推荐 |
| 给组件逐个添加颜色属性 | 局部接入直接 | 多层传递、漏改和颜色不一致风险高 | 不采用 |
| 引入第三方完整主题编辑框架 | 可获得复杂编辑能力 | 新依赖和设计体系迁移超出首期需要 | 不采用 |

延续根节点 CSS 变量和 class 暗色模式。自定义输入只有三种基础色；背景层级、边框、次要文字、悬停、选中态和焦点由同一主题解析器产生。此模式基于项目已有变量，并符合 [MDN CSS 自定义属性的继承与引用机制](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties)。

## 3. 页面与交互

### 3.1 页面顺序

1. **模式**：跟随系统、浅色、深色三种选择，以小型界面示意图表达；选中状态同时使用边框和文字标识，支持键盘操作。
2. **主题**：下拉选择「知序」「石墨」「海蓝」「暖砂」，已有自定义配置时增加「自定义」选项；每项提供小色样。知序主题完整复用当前浅色/深色基线。
3. **颜色**：强调色、背景色、文字色三行，每行由色块、取色器和 HEX 输入组成。显示「正在编辑：浅色配色/深色配色」。
4. **字体**：界面字体、代码字体分别选择；自定义本机字体时显示字体名称输入框和回退说明。
5. **效果预览**：紧凑样例包含中文、英文、数字、按钮、输入框及代码片段；真实应用同步变化。窄屏按单列排列。
6. **恢复默认外观**：独立文字按钮。原有语言与本地偏好设置保留，排在外观编辑区之后，不改变其保存行为。

参考图的主题复制、下载图标和「高级」入口不在首期范围内，不放置无功能按钮。

### 3.2 预设与自定义

- 四种预设各有浅色与深色配色。预设选择不改变模式与字体。
- 首次编辑预设中的任意颜色，复制当前预设为自定义基底，然后切换到「自定义」。
- 自定义分别存储浅色、深色的颜色覆盖；未编辑的模式继承其基底预设。
- 更换浅色/深色模式只切换所见配色，不覆写另一模式。跟随系统时，编辑目标就是当前实际模式，界面明确标示。
- 切到其他预设时保留已有自定义配置；再次选「自定义」恢复它。只有在用户开始编辑另一个预设时，才以新预设替换自定义基底，并清楚显示当前主题名。
- 单个颜色提供「恢复主题值」，仅删除当前模式下该字段的覆盖。它不影响另一个模式或字体。
- 「恢复默认外观」恢复知序预设、跟随系统和默认字体，清空自定义配置；不重置语言、密度等其他偏好。

### 3.3 颜色输入与可读性

- 接受 #RGB 与 #RRGGBB，允许省略 #，提交后统一为 #RRGGBB；不接受透明色、CSS 表达式或任意样式片段。
- 输入中的半成品保留在输入框草稿中；只有完整合法色值才更新主题。失焦时若无效，显示具体格式提示，保留上次有效主题。
- 色块和取色器保持一致；拖动时即时预览，以短延迟合并保存，最终值在交互结束时提交。
- 强调色用于主按钮、选中和焦点；按钮文字在深浅候选中选择可读性较好的颜色。
- 背景和文字保留用户选择，避免暗中改色；在设置区显示正文颜色与背景的对比度提示，允许用户调整。恢复默认按钮根据当前背景使用独立可读的文字色，防止极端配置导致无法恢复。
- 不将错误、警告、成功颜色全部改为强调色；状态仍可辨识。

### 3.4 字体

- 界面字体提供「系统默认」「无衬线」「衬线」「自定义本机字体」。系统默认延续中文和其他语言现有字体回退行为。
- 代码字体提供「默认等宽」「Consolas」「Cascadia Code」「JetBrains Mono」「自定义本机字体」，最终始终保留等宽与中文回退字体。
- 自定义输入是一个字体家族名称，限制长度并拒绝控制字符及样式分隔符；由代码进行引用和转义，不拼入 HTML/style 文本。
- 字体未安装时使用回退栈；说明文案不声称可检测或保证安装状态。[MDN font-family](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-family) 明确描述了按字体可用性与字符覆盖逐项回退的行为。
- 界面字体覆盖聊天正文、控件、欢迎标题等原先独立指定字体的位置；选择默认时保留欢迎标题原有风格。代码设置覆盖代码块、diff、文件预览等宽文本与终端，不受界面字体覆盖。

## 4. 状态、模块与保存

### 4.1 单一状态来源

在 App 现有 useTheme 所在位置管理外观状态，不在每个设置页单独创建主题状态。保留对外的已解析 theme = light/dark，保证现有 ThemeProvider/useThemeValue 消费者（含代码高亮）继续工作。新增 mode = system/light/dark，区分用户选择与实际模式。

现有 toggle 明确切到当前实际模式的相反显式模式；setTheme 明确选择 light/dark。设置页三选项使用新的 setMode。跟随系统时订阅媒体查询变化，离开跟随系统或组件卸载时清理订阅。依据：[MediaQueryList change](https://developer.mozilla.org/en-US/docs/Web/API/MediaQueryList/change_event)。

职责按以下边界划分，具体文件和并行契约在实施计划前确定：

- **主题模型与解析器**：预设、数据校验、迁移、色彩派生、字体栈；输入配置和实际模式，输出完整样式值；纯逻辑可独立测试。
- **状态与应用层**：本地存储、系统模式监听、根节点样式应用、上下文与跨标签页变化。
- **外观设置组件**：表单草稿、选择与预览，只调用状态层，不自行操作 localStorage。
- **页面适配**：将独立硬编码色/字体映射到语义变量；终端通过其选项 API 更新。

### 4.2 持久化数据

使用独立键 `zhixu-webui.appearance`，带 schemaVersion。存储模式、选中预设、自定义基底、自定义两套覆盖色、界面字体与代码字体。独立于 `zhixu-webui.settings-preferences`，不进入服务器配置或触发重启提示。

首次读取新键为空时，从 `zhixu-webui.theme` 迁移 light/dark；都不存在时默认跟随系统、知序主题、默认字体。保留 index.html 中旧品牌键的迁移链，不改写本次范围外的迁移规则。旧 theme 键可作为已解析模式的兼容镜像，新配置存在时以新配置为准，镜像不能反向覆盖 system 选择。

读取配置逐字段校验：未知预设、非法字体、损坏 JSON 和未知版本都安全回退；未来版本不自动覆写，等用户实际修改后再保存当前支持的结构。同一来源的多个窗口通过 storage 事件更新，不重复回写造成事件循环。

localStorage 按 origin 隔离，[MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) 说明其跨浏览器会话的保存行为。因此桌面端在现有固定 gateway 地址下可重启保留；切换端口、host、浏览器或设备不自动同步。存储不可用时本次会话仍能修改，显示「本次已生效，无法保存到此设备」，不假装保存成功。

### 4.3 首屏恢复

React 初始化前即恢复模式、背景、文字和字体，避免刷新先显示默认白色/绿色再切换。

采用配置解析器生成的双模式 CSS 快照：在外观存储记录中携带只读派生快照，包含预定义变量白名单及其版本、配置签名。head 内轻量同步脚本读取并校验，按系统模式选用快照；完整模型仍是配置，快照不是第二个可编辑来源。缓存缺失、签名或版本不符时回退安全默认，由运行时重新解析和修复；不执行存储里的脚本，不注入任意 CSS。

body 启动样式也引用恢复的变量；React 接管后完整应用语义变量并更新 theme-color。首屏脚本与运行时的输入校验规则保持一致，针对两种入口建立一致性测试。

## 5. 全局颜色与独立渲染器适配

| 区域 | 调整方式 |
| --- | --- |
| 全局基础与 Tailwind | 维持现有 HSL 变量消费格式，新增字体变量；不修改布局和圆角体系 |
| 背景、侧栏、卡片、菜单、弹窗 | 由背景与前景混合产生有层级的表面色、边框和次要文字，浅深模式分别处理 |
| 按钮、选中、焦点、滚动条、临时会话 | 使用强调色及派生变量，覆盖现有孤立的绿色值 |
| Teams 与 Agent 编辑页 | 替换充当界面底色/文字/强调色的固定色；保留成员身份色、图像和布局 |
| 欢迎标题与字体 | 移除对用户显式字体选择的硬覆盖，默认路径保留现有排版风格 |
| 代码块与 diff | 固定字体栈改为统一代码变量，基础文字/背景跟随外观；语法分类色继续随已解析明暗模式选择 |
| 终端 | 更新 xterm 基础前景、背景、游标、选区及代码字体，并重新 fit；不重建终端、不丢历史或 PTY 连接，保留 ANSI 语义色 |

xterm 不能仅靠修改祖先 CSS 完成更新；需要通过 [Terminal.options](https://xtermjs.org/docs/api/terminal/classes/terminal/#options) 设置字体和新主题对象。本地 TerminalEmulator 适配层须提供可选的外观更新能力，兼容现有测试替身。具体 API 以本地 6.0.0 类型声明为准。

预览模式入口也应展示同一外观设置组件与模型；保留其隔离机制，不调用真实 gateway、不修改真实用户偏好。

## 6. 验收标准

1. 四种预设在浅色和深色均有完整色板；知序默认主题与现有基线一致。
2. system 模式在系统改变时立即跟随；显式浅/深模式不跟随。旧主题偏好升级后保留。
3. 三个颜色均支持取色器和 HEX；合法值即时反映到真实界面，非法输入不污染最后有效状态。
4. 浅/深自定义互不覆盖；预设切换后能恢复已有自定义；单色恢复与整体恢复边界明确。
5. 刷新及同来源重启保留外观，首屏背景/文字/字体与运行时一致；损坏配置和存储不可用不会阻断启动。
6. 中文/英文界面字体及代码字体均生效，欢迎标题、代码块、diff、终端无固定字体覆盖；字体不存在时可回退。
7. 首页、聊天、设置、Agent 编辑、Teams 编辑、记忆与工作台实测覆盖；无残留的主题界面硬编码导致明显色板割裂。
8. 修改外观不会重连 gateway、重建会话或终端，不触发服务器配置保存或重启状态。
9. 明暗模式与颜色/字体控件具备可访问名称，支持键盘；窄屏不发生横向溢出。现有语言与本地偏好仍可用。

实施时使用针对性的主题模型、迁移、系统监听、非法输入、字体和首屏一致性测试，并执行 WebUI 构建与项目要求的测试。实际浏览器检查包含至少一套自定义浅色、一套自定义深色、恢复默认及多页面检查。终端需验证修改字体后历史与连接保留。正式桌面端重启若无法执行，报告为未验证，不用浏览器刷新替代声明。
