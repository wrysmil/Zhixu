# 知识库与检索评测台：现状分析与设计参考

用户确认范围为 `#/knowledge` 与 `#/knowledge-eval` 两个入口，涵盖其中的列表与详情。允许使用外部组件。本轮完成调研与布局研究，未修改业务代码或安装依赖；下述改版建议尚未成为批准的实施方案。

## 1. 结论

建议统一为「安静、清楚的知识工作区」：知识库以资料、搜索和处理状态为主；评测以记录、指标、退步题和证据为主。共同使用一致的字号、间距、边框、按钮和详情面板，但不强求两页完全相同的内容布局。

当前观感问题主要来自信息优先级和重复容器。外部组件能补齐表格筛选、抽屉和图表能力；单纯换组件库不会自动解决页面结构。

独立视觉研究：[双页布局示意](2026-11-11-knowledge-ui/layout-study.html)。上方按钮可以切换两页；数据全部为设计样例，其他操作为静态示意。导航仅表示层级关系，不建议据此修改知序全部全局导航。

## 3. 两页具体哪里不舒服

| 问题 | 当前证据 | 影响 | 建议 |
| --- | --- | --- | --- |
| 首页被统计占据 | 知识库顶部五张等权统计卡，空数据也全部显示 0；`KnowledgePage.tsx:663` | 先看见系统计数，之后才看见资料；空页面像监控后台 | 正常态压成一行摘要，异常时突出待处理或失败；完整索引统计保留在次级入口 |
| 字号过小、重点相近 | 两页内容常用 10.5–13px；评测数字仅 15px，公式约 10px；`KnowledgeEvalOverview.tsx:98` | 核心指标没有成为视觉焦点，中文长文本阅读吃力 | 标题约 26–28px，区块 16–18px，正文 14px，辅助 12px，关键指标 26–30px |
| 面板嵌套和装饰重复 | 评测外层 section、每个 dataset 卡片及题目行逐层包裹；`KnowledgeEvalDatasets.tsx:78/214/243` | 边框承担了过多分组工作，看起来像表单拼装 | 一级页面用留白分区，列表主要靠行分隔；仅内容实体或弹层使用完整边框 |
| 数据集列表展开全部问题 | `KnowledgeEvalDatasets.tsx:243` 直接遍历每题及标注输入框 | 题集一多，首页成为持续增长的编辑表单 | 题集首页显示名称、题数和标注摘要；点击进入题目表，标注按行编辑 |
| 新建运行表单优先于结果 | `KnowledgeEvalRuns.tsx:111` 起显示配置，运行列表在 `:253` | 回来看结果必须先越过配置字段 | 有历史数据时默认进入评测记录；新建评测用抽屉/对话框，高级参数折叠 |
| 首屏没有清楚的任务动作 | 知识库维护按钮与创建并列；评测头部主要为指南和刷新 | 每页的主要用途缺乏视觉锚点 | 知识库突出新建/添加资料；评测突出新建评测。修复和刷新收为次级操作 |
| 空状态缺少直接操作 | 大虚线框里只有标题与解释 | 空间大，却没有帮助完成第一步 | 知识库提供创建按钮；评测提供导入模板/创建题集。模板下载作为辅助链接 |
| 详情元数据偏技术化 | 评测报告头与面包屑突出 run ID；`KnowledgeEvalPage.tsx:389` 附近 | 很难凭名字辨认本次评测做了什么 | 优先展示题集名、配置摘要、时间与状态，完整 ID 可复制但降为辅助 |

这些是设计判断，不代表功能错误。知识库现有文档/检索/图谱分区、评测已有的聚合+逐题、缺证据不补零等，应保留其业务语义。

## 4. 网上哪些产品值得学

| 产品与官方来源 | 已核实模式 | 对知序的借鉴 |
| --- | --- | --- |

| [Dify 检索测试](https://docs.dify.ai/en/cloud/use-dify/knowledge/test-retrieval) | 检索测试单独入口；测试设置临时生效；保留检索记录 | 日常资料管理与诊断分开。知序现有检索 Tab 可以保留，参数放在诊断区 |
| [Outline](https://www.getoutline.com/) / [官方界面图](https://www.getoutline.com/images/screenshot.png) | 官方图示呈现集合树、面包屑、独立目录与正文；界面围绕阅读展开 | 借鉴节制的边框、文字层级与内容主导。无需复制团队权限与协作功能 |
| [Notion Wiki](https://www.notion.com/help/wikis-and-verified-pages) | 所有者、内容验证状态、过期提醒和搜索中的验证标记 | 学习让状态承担明确含义。知序的「索引就绪」与「内容人工核实」必须区分，首期不新增验证制度 |
| [WeKnora 官方仓库](https://github.com/Tencent/WeKnora) | 知识库、文档组织、引用溯源和图谱等围绕资料使用形成完整链路 | 中文知识管理的业务参考；不能把企业平台所有入口、权限和管理复杂度一并搬来 |
| [Langfuse 实验比较](https://langfuse.com/docs/evaluation/experiments/compare-experiments) | 先比较聚合指标，再筛选问题题目、并排查看结果并深入 trace | 报告有结论、有差异、有证据。知序只借鉴检索相关部分，不扩张为回答质量评测 |
| [LangSmith 实验比较](https://docs.langchain.com/langsmith/compare-experiment-results) | 表格筛选、列显隐、退步/改善计数可点击筛题；点行打开详情 | 两运行对比优先，点击退步立即定位对应问题；默认控制宽表列数 |

事实和推导边界：上表第三列是对知序的设计建议，不代表竞品原样如此，也不代表知序当前已有这些能力。

## 5. 三种改版方向

| 方向 | 做法 | 收益与代价 |
| --- | --- | --- |
| A. 保守视觉整理 | 保留全部布局，统一字号、按钮和边框 | 改动较小，但数据集全部展开、运行表单挡住结果等结构问题仍在 |
| **B. 资料工作区 + 评测工作台（推荐）** | 知识库以资料为中心；评测以历史和结果为中心；统一视觉基础 | 解决主要层级问题，能复用现有接口与组件；需调整前端结构和交互状态 |
| C. 完整 Wiki/实验平台 | 新增编辑器、复杂目录、团队标注、多实验矩阵 | 适合不同规模产品，明显扩大范围和依赖；不作为本次改版目标 |

## 6. 推荐的页面组织

### 知识库

首页顺序：标题与创建 → 简短状态摘要 → 搜索/范围筛选/排序 → 知识库内容。少量库用卡片，多量库再考虑列表；卡片只放图标、名称、两行描述、文档数、更新时间、处理状态。更新/范围筛选必须基于当前数据字段与接口能力；暂无数据就省略，不填虚构时间。

详情顺序：面包屑/库切换 → 库名与添加资料 → 文档、检索测试、知识图谱 → 对应工作区。文档 Tab 为表格，上传文件作为主要操作，服务器路径导入留在添加资料面板；预览片段用现有 Sheet 思路保留文档列表上下文。图谱保持独立 Tab，避免当装饰图占首页。

搜索框必须明确是「搜索库名称」还是「搜索资料内容」，两者不能混为同一语义。跨库最近文档只属于可选增强，需要进一步核对聚合接口；不是首期设计依赖。

### 知识库评测

有运行时默认评测记录，没有运行但有题集时给出开始评测入口，两者都空时引导创建/导入题集。导航仍保持记录、测试题集、对比的稳定位置。

新建评测按需打开：先选题集和知识范围、再选检索配置，默认参数与高级参数分开。不可因视觉整理删除隐私确认、运行取消与降级提示。

报告顺序：题集名与运行摘要 → 指标 → 逐题表 → 选中题目的召回片段与评分证据。Precision、Recall、Hit、MRR、nDCG 五项仍保留；核心指标可以较大，其余较轻，但不要丢失。指标公式从当前 API 获取，放入帮助或展开解释，避免卡片内塞满小字。K 与运行配置一致，不写死为示意图里的 5/10。

对比顺序：固定基准/候选 → 可比性说明 → 指标差值 → 改善/退步/未评分筛选 → 双侧片段证据。未评分显示「—/未评分」，与 0 分、任务错误分开；人工 expect 与 judge 分组保留，降级运行不能伪装为可直接比较。

本项目目前是检索级评测：不要使用「回答正确率」「答案质量已提升」等超出证据的文案。成本、回答生成进度、完整调用树等竞品能力不应因为参考设计就新增到本页。

## 7. 外部组件如何选

| 能力 | 选择建议 | 目的及约束 |
| --- | --- | --- |
| 按钮、弹层、菜单、抽屉、提示 | 优先复用已有 Radix + Tailwind 组件 | 项目已有 Dialog/Sheet/Combobox/Tooltip 等，无需为了改两页引入第二套全局主题 |
| 题集、运行、逐题结果表 | [TanStack Table](https://tanstack.com/table/latest/docs/overview) 配合 [shadcn Radix Data Table](https://ui.shadcn.com/docs/components/radix/data-table) 思路 | 获得筛选、排序、列显隐和选择；TanStack 是逻辑引擎，不自带漂亮外观，仍需统一设计 |
| 指标对比图 | 可选 [shadcn Radix Chart](https://ui.shadcn.com/docs/components/radix/chart) / Recharts | 双运行对比适合简单条形图；没有历史数据不绘制趋势线，也无需先引入大图表库 |
| 文档和单题详情 | 复用现有 Sheet，参考 [shadcn Sheet](https://ui.shadcn.com/docs/components/radix/sheet) | 保留表格上下文，处理焦点与关闭后的焦点恢复；小屏转换为完整面板 |
| 图谱 | 先继续使用现有 d3-force | 本轮核心问题不依赖更换图谱引擎；避免新增大型图形依赖来掩盖页面层级问题 |

版本边界：当前本机 React 18.3.1、Tailwind 3.4.19；shadcn 有 Base UI/Radix 两条入口，TanStack latest 当前已是 v9。实施时应选择并锁定兼容版本及对应文档，不能直接套旧教程或盲装 latest。本次没有完成新库的集成兼容性验证，不指定未经安装验证的精确新版本。

## 8. 视觉标准与后续验收

- 浅中性背景、白色内容面、单一克制强调色；示意图采用低饱和绿，仅作为可讨论方向，正式落地复用项目主题变量并覆盖暗色。
- 间距围绕 8/12/16/24/32px；输入与按钮约 36–40px；圆角约 6–10px，胶囊仅用于筛选/状态等合适语义。
- 同一局部优先只有一个主动作；新建和删除等操作有独立位置，删除与修复进入有文字的菜单，不只靠图标辨认。
- 长文档名、长问题、中文换行、失败/处理中/未评分、空状态均要设计。表格可横向滚动，页面整体不可溢出。
- 对应实施阶段应检查 1440 与 1280 宽度、窄屏、深色、键盘焦点、长内容；验证现有上传、检索、图谱、题集导入、取消运行和对比行为。
- 对比完成标准：首屏能快速找到资料或评测记录；开始评测不必穿过大段参数；退步题可以从摘要定位到片段证据。
